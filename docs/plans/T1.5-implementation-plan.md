# T1.5 implementation plan

> Active plan. `MILESTONES.md` owns T1.5's status and acceptance gates; this
> file owns only the order in which the work lands. Freeze it at the gate close.

## Outcome

Keyboard operation of Live Control through **one command registry**: every
Presenter key, its keycap text, its label and the focus contexts it may run in
come from one table in `crates/ordo/src/commands/registry.rs`. GPUI key
bindings and the Keyboard shortcuts reference are both derived from it, and
every key still reaches the Engine only through `commands::dispatch`. Text
entry, emergency editing and true modals suspend every single-key command;
passive surfaces (Ordo rail, shortcut reference) leave only `F`, `B` and
`Space` active.

## Shaping constraints (verified)

- **The Engine is complete.** `presentation::commands::Command` already has
  `Next`, `Previous`, `NextItem`, `PreviousItem`, `First`, `Last`, `Take`,
  `ToggleFreeze`, `ToggleBlackout`, `ToggleAutoPlay`, `LoopSection`,
  `StopAutoPlay`. T1.5 adds no Engine command; it is UI wiring only.
- **Today only the labs bind keys** (`examples/live-control-lab.rs:480`,
  lab-local `actions!`). T1.5a moves the Presenter keys into the registry;
  the lab keeps only its development keys (`E`, `D`, `R`) and takes the
  Presenter bindings from `commands::registry::key_bindings()`.
- **Key map** (`MVP-PLAN.md` §8.2): Left/Up previous, Right/Down next,
  PageUp/PageDown item, Home/End first/last, `F`, `B`, `A`, `O`, `Space`,
  `Esc`, `F6`/`Shift+F6`; `Ctrl+/` toggles the reference (§6.33, no bare `?`).
  `Insert`, `Ctrl+E`, `Ctrl+R` belong to emergency editing (later tasks) and
  are not registered now.
- **GPUI context predicates (verified, `gpui-pre-0.3.8/src/keymap/context.rs:291`).**
  `!X` is false if *any* context on the focus stack matches `X`, so the
  predicate `Presenter && !TextEntry && !Modal` suspends a binding whenever a
  text field or modal anywhere above focus declares that context. The handler
  checks the pure policy again (defence in depth), so a binding that slips
  through still never reaches the Engine.
- **Focus contexts** (pure enum, no GPUI): `Timeline`, `Dock`, `Rail`,
  `ShortcutReference`, `TextEntry`, `Modal`, `Elsewhere`. Policy:
  - *Output* entries (`F`, `B`, `Space`): Timeline, Dock, Rail,
    ShortcutReference, and also active Elsewhere inside the Presenter, e.g.
    header controls.
  - *Operating* entries (navigation, `A`, `O`): Timeline, Dock only.
  - *Surface* entries (`Esc`, `F6`/`Shift+F6`, `Ctrl+/`): owned by the surface
    or region system, listed in the reference; never reach the Engine.
  - TextEntry, Modal: nothing single-key.
- **F6 regions** reuse `ui::accessibility::RegionRegistry` (already binds
  `f6`/`shift-f6` to `NextRegion`/`PreviousRegion` in `ui::key_bindings`).
  Visible regions in order: Ordo rail (only when pinned or the overlay is
  open), Cue timeline, Output controls. Region changes never send a Command.
- **Esc** closes only the topmost temporary surface (shortcut reference, then
  rail overlay, then nothing) and returns focus to the timeline, which owns
  the active-Cue focus. It never collapses a pinned rail. With nothing open,
  Esc from the rail, Output controls or any other control (the header)
  returns focus to the timeline; from the Cues it does nothing and
  propagates. A scrim press closes the same topmost surface. `F6`/`Shift+F6`
  from inside the open overlay closes it (no keys act under a scrim).
- **Accessible names** use the existing `aria_label`/`role` support; Cue names
  are built by a pure function from `CueModel` (position, text/type,
  project/wait/hold/Blackout behaviour), operator-side only.
- **Announcements** use `ui::accessibility::StatusAnnouncement` (polite);
  urgent safety announcements are a later `[MANUAL]` check.

## Work packages

1. **WP1 — registry and key dispatch** (AC1 registry half, AC5, AC6 policy).
   *design-sensitive + GPUI-facing → Sonnet.* Files:
   `crates/ordo/src/commands/{mod.rs,registry.rs}`,
   `crates/ordo/src/presenter/mod.rs`, `crates/ordo/examples/live-control-lab.rs`,
   `crates/ordo/src/main.rs`/`shell.rs` only to register bindings.
   - `registry.rs`: `actions!(presenter, [...])`; `pub struct Entry { action,
     keys: &'static [&'static str], keycaps, label, group, scope }`;
     `pub static ENTRIES`; `pub enum FocusContext`; `pub fn allows(scope,
     context) -> bool`; `pub fn key_bindings() -> Vec<KeyBinding>`;
     `pub fn command_for(entry) -> Option<Command>`.
   - `PresenterView` root: `.key_context("Presenter")`, one `on_action` per
     registry action; handler resolves the current `FocusContext` from its
     focus handles (adds a `dock_focus`), checks `allows`, then `dispatch`.
   - Tests: keys parse; no keystroke registered twice in one context; the
     derived bindings cover every entry; `allows` exhaustive table; UI tests
     that `space`/`f`/`b` from rail focus reach the Engine and `right` does
     not; a test element with `key_context("TextEntry")` swallows `f b o space`.
2. **WP2 — O, Esc, F6** (AC2, AC4). *GPUI-facing → Sonnet.*
   `presenter/{mod.rs,rail.rs,dock.rs,timeline.rs}`.
3. **WP3 — auto-play controls** (AC3). *GPUI-facing → Sonnet.*
   `presenter/{dock.rs,mod.rs}`: an Auto-play control in the Dock with a menu
   (Start/Stop auto-play for this item, Loop this section, Stop); disabled
   entries and `A` on ineligible content show the refusal sentence.
4. **WP4 — shortcut reference** (AC1 reference half). *GPUI-facing → Sonnet.*
   New `crates/ordo/src/shortcut_reference/mod.rs`: a viewport-bounded right
   panel listing registry groups, current context first; `Ctrl+/` toggles it,
   `Esc` closes and restores prior focus; entry points in the header and rail
   footer. A test asserts every reference row comes from `ENTRIES`.
5. **WP5 — Cue focus names** (AC7). *mechanical → Haiku/Sonnet.*
   `presenter/timeline.rs`: pure `cue_accessible_name` + tests; never read by
   the congregation renderer. Cue focus names need either focusable Cue tiles
   or an active-descendant name on the timeline container; Esc's "restore
   active Cue focus" then targets that.
6. **WP6 — E2E** (E2E line). *GPUI-facing → Sonnet.* `presenter/e2e.rs`
   keyboard pass (focus each region and overlay, exercise every registered
   key, type `fbo` and spaces into a text field), MILESTONES ticks, freeze.

## Open decisions (defaults chosen unattended, for owner review)

1. `O` is inactive while focus is in the rail itself (the AC lists only F/B/Space
   for passive focus); pressing it there does nothing.
2. Arrow keys in the rail move within the rail list, not the Cues.
3. `Ctrl+/` stays available in text fields (it is chorded) but not in a modal.
4. F6 order: rail → timeline → Output controls; the header is not a region.
5. The Keyboard shortcuts panel takes focus on itself when it opens (not on its
   close button, as `DESIGN.md` says for slide-overs): it is passive, so Esc
   and `Ctrl+/` close it from anywhere inside, and a focus handle on the panel
   is what makes the focus context `ShortcutReference`.
6. The panel stays open when `F6` leaves it (it is passive, not a trap); `Esc`
   still closes it and restores the focus it was opened from. Clicking the
   rail scrim while it is open closes the panel first (the topmost surface).
7. The header entry is an icon (the existing question-mark glyph) with the
   label "Keyboard shortcuts" in the Constrained layout, and icon plus label
   elsewhere; no new icon is vendored for it.
