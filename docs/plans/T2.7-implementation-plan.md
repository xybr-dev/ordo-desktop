## Outcome

The operator writes an Arrangement's lyrics once, in sections, and controls where slides break:

- The focused Arrangement view becomes the **Arrangement editor** with two task tabs, **Lyrics** and **Sequence**. Metadata stays behind **Arrangement details**.
- An Arrangement with no sections shows **No sections yet** and a focused **Add first section**. Nothing is created until the operator adds a section; Ordo never adds Verse 1 on its own.
- **Add section** opens a small popover with one required name, prefilled with a numbered suggestion and offering editable suggestions. Names are free-form, non-blank and unique within the Arrangement. **Add section** stores the section, selects it and focuses its lyric editor.
- The lyric editor is plain multi-line text. A newline continues the slide; a blank line starts the next one; deleting the blank line joins the two slides. **Split after line N** and **Join slide N with slide N-1** sit next to each other below the editor, and Join is disabled on the first slide.
- The generated slides show as fixed-size 16:9 canonical thumbnails that wrap. Selecting one selects its source lines and drives the single Inspector.
- Sections can be renamed, reordered (buttons or `Alt+Up` / `Alt+Down`, authoring order only) and removed. Removing a section the Sequence uses asks for confirmation and removes its occurrences in the same edit. **Undo** puts everything back.
- Lyric typing autosaves after 1 s idle or when focus leaves. Structural changes (add, rename, move, remove, Split, Join) save at once. The header shows **Saving…**, **Saved** or **Couldn't save**.

## Facts found in the code

**Domain (sections, lyrics, boundaries today)**
- A section is `Section { id, label: Option<String>, lyrics: String }` (`crates/domain/src/song_library/model/arrangement.rs`, `SectionDraft` line 39). The label is optional and only checked for blankness; there is no uniqueness rule. Products call it a name; the code calls it `label`.
- Slide boundaries have no representation. Lyrics are stored verbatim; nothing parses blank lines. `crates/domain/src/pagination/` does not exist.
- Section order is the order of `ArrangementContent.sections`; Sequence is `Vec<Occurrence { id, section }>`. `ArrangementContent::validate` already rejects occurrences naming a section outside the Arrangement and duplicate ids.
- Pagination review is one `PaginationState` per Arrangement (line 28). `pagination_content_changed` (line ~593) moves Approved to NeedsReview when the Sequence changes or any section is added, removed, or has its lyrics **or label** changed; section order alone does not count.
- `SongLibrary::edit_arrangement` (`interface.rs:526`) replaces the whole content, metadata included, and applies the review rule. `refresh_arrangement` (`:560`) takes stored values with no rule. `approve_pagination` exists (`:918`). Section and occurrence identities stay reserved to their first Arrangement forever (`require_free_section_and_occurrence_ids`, `:1238`).
- `match_key` (case and spacing fold) is public and is the right key for name uniqueness.
- `domain::revisions` has `TextCoalescer`, `UndoStack<C>`, `SessionClock`, `EditPoint` (`crates/domain/src/revisions.rs`).

## Shaping constraints

- **Changes paths.** `crates/domain/src/song_library/sections.rs` and `crates/domain/src/pagination/manual_boundaries.rs` can be created as written (T3.1 later adds `interface.rs`, `proposal.rs`, `validation.rs` to the same `pagination` module). `crates/ordo/src/songs/lyrics/` is new. `tests/e2e/songs/lyrics.*` does not exist: as for T2.4-T2.6 the E2E lives in `crates/ordo/src/songs/e2e.rs`. WP8 amends the Changes line.
- **Boundaries stay in the text.** Decision 116 and MVP-PLAN 6.17 make the blank source line the boundary. Split and Join therefore rewrite the lyric text, and the domain owns the parsing so T2.8 (child slides), T2.10 (Markdown) and T3.1 (proposals take "intentional boundaries" as input) all read the same rule. Stored text is never normalized.
- **No migration is needed** for names, boundaries or reorder. A migration appears only if per-section approval is adopted now (Decision 3).
- **Lyrics commits must not overwrite metadata.** The details panel commits metadata through `commit_arrangement_metadata`, which reads sections in-transaction. The lyrics commit must be its mirror: read head revision and metadata in the same transaction and replace only sections, Sequence and pagination state. Otherwise a lyrics autosave after a details Save would write stale metadata.
- **Undo must restore approval.** The revision payload has no pagination state, and the domain rule recomputes it on every edit (Approved → NeedsReview). So the editor's content type carries the pagination state, and the lyrics commit writes the state it is given. Forward edits compute it with the domain rule before committing; Undo commits the earlier snapshot, state included (AC9, MVP-PLAN 6.17 "Undo restore the complete section content, pagination/approval state, and occurrences").
- **The store must not clobber the working copy.** `LibraryEvent::Changed` fires on every write, including the editor's own. The editor reloads its text only on `EditSessionEvent::ContentReplaced` (Undo/Redo/leave), never from the library while a session is open.
- **No caret event.** Which slide is selected follows the caret only when the view reads `cursor()` during render; the plan derives the selected slide in render from the byte offset with a pure domain function (cheap, no subscription).
- **Thumbnails compose off the GPUI thread** (`AGENTS.md`). Compose with `rendering::compose` on the background executor, keyed by (header, body), only for the selected section's slides; keep the tasks owned by the Lyrics view and drop stale ones.
- **Section and occurrence ids.** Storage generates ids only on creation. For edits the caller supplies them (`SectionContent.id`), so the view mints a `SectionId` from a v4 UUID when a section is added, as `fresh_session` does.
- **First production `EditSession`.** It needs a `RevisionPort` over `LibraryStore` (holding `WeakEntity<LibraryStore>` and an `AsyncApp`, because `commit` gets no context), and the shell must call `request_navigation` on Back, window close and quit and handle `Blocked` with **Retry save**, **Keep editing**, **Leave without saving** (MVP-PLAN line 834).

## Decisions made while planning (owner to confirm)

1. **Boundary syntax.** A slide group is a run of lines with non-whitespace content. Any run of one or more whitespace-only lines is one boundary; leading and trailing blank lines make no slide. `\r\n` counts as a newline. The slide body is the group's lines with trailing whitespace trimmed, for rendering only; stored text is never rewritten. *Reason:* matches the mockup's `/\n\s*\n/` and survives paste.
2. **Split and Join are minimal text edits.** Split inserts one `\n` after the target line; Join replaces the whole blank run between the two groups with one `\n`. Everything else stays byte-for-byte. *Reason:* keeps authored text and the caret stable (the mockup re-joins everything, which would normalize spacing).
3. **Approval stays per Arrangement in T2.7; per-section approval and Approve pagination wait for T2.8.** T2.7's AC needs approval only to survive Undo. Per-section state (mockup B's "the Koro … needs review"; MVP-PLAN "readiness considers only referenced sections") is a T2.8 readiness need and would cost migration 0007, a revision format 3 and a hydration change. The Lyrics content type carries the state as a field so it can become per-section without changing the editor. *Reason:* keeps T2.7 inside its AC. *Alternative:* do it now as `arrangement_section.pagination_state` (0007, backfilled from `arrangement.pagination_state`).
4. **Any lyric change, boundary edits included, follows the existing review rule** (Approved → NeedsReview). The mockup's interpretation "Split and Join leave the approval as it was" conflicts with Decision 18 ("changing … intentional line breaks … marks Needs Review"); the decision record wins over a mockup interpretation (`DESIGN.md`, Approved References). *Reason:* one path-independent rule.
5. **Renaming does not trigger review.** MVP-PLAN 6.17 says rename preserves approvals, and Decision 18 puts labels in a reserved area outside the line budget. `pagination_content_changed` stops comparing labels. *Reason:* the plan and the record agree; the code was stricter.
6. **Rename is in scope** (mockup A's name field in the section header; Enter renames, Esc cancels; toast "Renamed X to Y. Every Sequence occurrence shows the new name."). *Reason:* uniqueness has to hold for renames too, and no other task owns it.
7. **Names.** Unique by `match_key` within the Arrangement. Enforced only where a name is introduced, on add and rename (changed after review: a committed snapshot must always be committable again, so Undo works on stored duplicates); the whole lyrics edit checks only that a present name is not blank. Names are trimmed. Duplicates already stored are kept (same leniency as held languages). Unlabeled sections stay valid in the domain (T2.10 `[Unlabeled]`); the UI shows them as *Unnamed section* and any rename needs a name. Error copy: "Another section is already called {name}." and "A section needs a name." (the second is the mockup's toast text). *Reason:* AC3 plus Decision 260.
8. **Suggestions.** The popover prefills the next numbered verse, including **Verse 1** for the first section, and offers chips: English → Verse N, Chorus, Refrain, Bridge, Ending; Cebuano → Bersikulo N, Koro, Katapusan; other languages use the English set. Suggestions already taken are left out. The first language decides. *Reason:* the E2E creates "Verse 1" and "Chorus" by keyboard, which the mockup's fixed list (no Chorus, blank first name) does not support; a prefilled editable field is not a fabricated section (AC2).
9. **Reorder is buttons plus `Alt+Up` / `Alt+Down` on the focused section row; no drag in T2.7.** Move up / Move down appear on the selected row (mockup). *Reason:* the AC names keys and Undo only; `ui` has no drag primitive yet.
10. **New sections are appended** at the end of the Lyrics list (mockup `commitPopover`). *Reason:* approved behavior; order is authoring-only.
11. **Split target is the middle of the selected slide**, `ceil(lines / 2)`, and the label names it ("Split after line 2", line counted within the slide). A one-line slide shows a disabled **Split slide**; slide 1 shows a disabled **Join with previous slide**. *Reason:* mockup interpretation 3. Splitting at the caret line can come later.
12. **Remove section.** A quiet destructive **Remove section** button in the section header (not a key). Unused: removed at once, toast "Removed {name}." with Undo. Used: a dialog first, title "Remove {name}?", text "{name} is sung {n} times in the Sequence. Removing it also removes those {n} occurrences.", primary **Remove section**, secondary **Cancel**. *Reason:* MVP-PLAN 6.17; the mockups show no removal, so this copy is new and needs approval.
13. **Thumbnail header is the section name** (Lyrics template with label on). *Reason:* mockup `slides()` uses the name; label visibility is Theme work later.
14. **Sequence tab in T2.7** is selectable and shows the current Sequence read-only (position and section name), with "Editing the Sequence isn't available yet". *Reason:* the T2.4 rule for unbuilt targets; it also lets the E2E check that Sequence order is untouched.
15. **One History session per editor visit.** The lyrics port uses the `EditSession`'s session ids; a details Save keeps its own session. *Reason:* MVP-PLAN 6.18 ("Keep Lyrics/Sequence work together for one Arrangement").
16. **Opening Arrangement details flushes lyric text first** (the editor's focus leaves, `focus_left` commits). Duplicate therefore copies the just-saved lyrics. *Reason:* Duplicate copies stored content (T2.6 Decision 4).
17. **Editor keys join the command registry.** Add `Group::Editing` and a non-Engine scope with entries `Alt+Up` / `Alt+Down` ("Move section up / down", context `LyricsSections`) and `Ctrl+Z` / `Ctrl+Y` ("Undo / Redo", context `EditSession`); `key_bindings()` derives them, the reference lists them, and `harness::init`'s private bindings move into the registry. *Reason:* T1.5 AC1, one registry for keys and reference; Decision 232 names an Editing group.
18. **Constrained width.** Three fixed panes at or above the minima (240 / 520 / 300). Below that, only the first adaptation: the Inspector moves to a labeled **Inspector** slideover. The full two-step adaptation stays with T3.8. *Reason:* `DESIGN.md` forbids horizontal workspace scroll; 1366 at 125% is already tight.
19. **Add section is an anchored popover** added to `ui::overlay` (focus trap, Esc, restore focus, placed with `gpui::anchored` at the invoker). *Reason:* MVP-PLAN "compact anchored popover". *Fallback:* `Overlay::dialog` if the popover costs more than one package.

### WP3: Lyrics commit (T2.7a). Storage, design-sensitive: write isolation. AC8, AC9.

## Risks / unknowns

- **Textarea is unqualified.** `TextareaMode` shares `Field`'s engine but has not been checked for IME, AccessKit role, Tab leaving the field, soft wrap at large Interface scale, or High Contrast focus. Budget WP5 for real evidence, not a wrapper only.
- **Native Undo vs editor Undo.** `set_value` after Split/Join or Undo drops the field's native history; a stale native Undo after a structural edit would revert text the session already committed. Test `Ctrl+Z` in the field right after a Split.
- **Caret sync without an event.** Reading `cursor()` in render works only while the view re-renders on caret moves (blink and selection notify the input entity, not the Lyrics view). The Lyrics view may need `cx.observe` on the textarea entity; watch for render loops (see the `set_placeholder` warning in `field.rs`).
- **Byte offsets.** `cursor()` and `set_selected_range` take UTF-8 bytes; domain ranges must be bytes too, and Cebuano text with diacritics will catch any char-index slip.
- **Working copy overwritten by `LibraryEvent::Changed`.** Reloading the field from the library on every store event would drop pending typing; reload only on `ContentReplaced`.
- **Stale metadata.** Using `commit_arrangement_edit` with memory's metadata instead of the new in-transaction lyrics commit would undo a details Save made during the session.
- **Pagination state in the content type.** Typing back to the original text still leaves NeedsReview, so a revision with unchanged sections may be written. Acceptable; the alternative (comparing with the session baseline at commit) belongs in `reviewed_against` if the owner minds.
- **Undo restoring `created_at`.** `commit_arrangement_in` gives a re-added section a new `created_at`; Undo of a removal cannot restore it. Harmless unless History (T2.9) shows it.
- **Thumbnail cost.** Composing on every keystroke is fine for one section; composing all sections or every key repeat on the GPUI thread is not. Keep compose off-thread and keyed.
- **Registry change touches the Presenter.** Adding `Group::Editing` and a new scope must keep the Presenter predicates and the reference tests (`every_registry_entry_is_listed_exactly_once`) green; `Alt+Up` must not leak into the Presenter.
- **Quit path.** The Quit Ordo? dialog runs before the flush today; the flush must run on **Quit** and a `Blocked` result must keep the window open.
- **Section ids from the view.** A reused id (Undo of a removal re-adds the same id) must pass both the domain reservation rule (same Arrangement: allowed) and storage's `require_not_foreign`.
- **Overflowing slides.** A 5+ line group renders whatever the renderer returns; there is no fit warning until T3.1. The E2E must use groups of at most four lines.
