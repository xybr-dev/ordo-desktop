# T0.7 implementation plan

> Active plan. `MILESTONES.md` owns T0.7's status and acceptance gates; this
> file owns only the order in which the work lands. Freeze it at the gate close.

## Outcome

Prove asynchronous local persistence: one supervised worker thread owns the
bundled `rusqlite` connection, callers see only domain-shaped async operations,
and a numbered, checksummed, transactional migration runner refuses newer
schemas and rolls back failed migrations completely. One PR from three work
packages, each ending in `cargo xtask verify`.

Constraints that shape the split:

- **Driver pin.** `rusqlite = { version = "=0.40.2", features = ["bundled"] }`
  in `[workspace.dependencies]`, used only by `storage`. No other crate may name
  it; `rusqlite::Connection` never appears in a public signature.
- **No new executor.** Replies travel over `async-channel` (already a workspace
  dependency) as one-shot `bounded(1)` channels, so any executor — GPUI's
  background/foreground executors included — can await them. Tests block with
  `futures-lite` `=2.6.1` (already locked) as a dev-dependency.
- **Checksums** use `sha2 = "=0.10.9"` (already locked), hex SHA-256 of the
  migration SQL bytes.
- **No SQL from callers.** The public surface is `Storage` methods returning
  futures of typed values. Fault injection (panic, delay, extra broken
  migration) exists only behind the non-default `fault-injection` cargo
  feature, enabled solely by test crates' dev-dependencies.
- **Domain shape for the spike.** Migration `0001_parish_profile.sql` creates
  `parish_profile (id INTEGER PRIMARY KEY CHECK (id = 1), name TEXT NOT NULL)`
  and `0002_parish_note.sql` a child table `parish_note (id INTEGER PRIMARY KEY,
  profile_id INTEGER NOT NULL REFERENCES parish_profile(id), body TEXT NOT
  NULL)` so foreign keys are observable. Operations: `set_parish_name`,
  `parish_name`, `add_parish_note`, `parish_note_count`, `schema_status`,
  `shutdown`.
- **Manual review** in the real app via `cargo run -p ordo --example storage-lab`.

## Storage Interface (fixed by WP1, consumed by WP2/WP3)

```rust
pub struct StorageConfig { pub path: PathBuf, pub busy_timeout: Duration }
impl StorageConfig { pub fn new(path: impl Into<PathBuf>) -> Self } // 5 s busy timeout

pub struct Storage; // owns Sender<Request> + Option<JoinHandle<()>>; Clone is NOT derived
impl Storage {
    /// Spawns thread "ordo-storage"; never blocks the caller. Open + migrate run
    /// on the worker; the result arrives through `ready()`.
    pub fn spawn(config: StorageConfig) -> Storage;
    pub fn ready(&self) -> impl Future<Output = Result<SchemaStatus, StorageError>>;
    pub fn schema_status(&self) -> impl Future<Output = Result<SchemaStatus, StorageError>>;
    pub fn set_parish_name(&self, name: String) -> impl Future<Output = Result<(), StorageError>>;
    pub fn parish_name(&self) -> impl Future<Output = Result<Option<String>, StorageError>>;
    pub fn add_parish_note(&self, body: String) -> impl Future<Output = Result<i64, StorageError>>;
    pub fn parish_note_count(&self) -> impl Future<Output = Result<u64, StorageError>>;
    /// Checkpoints WAL (TRUNCATE), closes the connection, joins the thread.
    pub fn shutdown(self) -> impl Future<Output = ShutdownOutcome>;
}
// Drop without shutdown: sends Shutdown, does not join (never blocks).

pub struct SchemaStatus { pub version: u32, pub applied: Vec<AppliedMigration>,
                          pub journal_mode: String, pub foreign_keys: bool }
pub struct AppliedMigration { pub id: u32, pub name: String, pub checksum: String }
pub enum ShutdownOutcome { Clean, WorkerPanicked(String), AlreadyStopped }
pub enum StorageError {           // thiserror-free; impl Display + Error by hand
    NewerSchema { found: u32, supported: u32 },
    ChecksumMismatch { id: u32 },
    MigrationFailed { id: u32, message: String },
    NotReady,                     // op before a successful open
    WorkerPanicked(String),       // this request's handler panicked
    WorkerUnavailable,            // channel closed / worker gone
    Busy,                         // SQLITE_BUSY after busy_timeout
    Sqlite(String),               // other driver error, message only
}

#[cfg(feature = "fault-injection")]
impl Storage {
    pub fn spawn_with_extra_migration(config: StorageConfig, id: u32, name: &'static str, sql: &'static str) -> Storage;
    pub fn inject_panic(&self) -> impl Future<Output = Result<(), StorageError>>;
    pub fn inject_delay(&self, d: Duration) -> impl Future<Output = Result<(), StorageError>>;
}
```

Worker rules: requests are processed strictly FIFO from one unbounded channel
(deterministic serialization); each handler runs inside `catch_unwind`; after a
panic the worker replies `WorkerPanicked` to that request, drops the connection,
and exits, so later requests get `WorkerUnavailable` and `shutdown` reports
`WorkerPanicked`.

Open sequence (order matters for "refused without mutation"): open connection
→ read `ordo_migrations` ledger if it exists (read-only) → refuse
`NewerSchema` if max id > bundled head, `ChecksumMismatch` if any applied
checksum differs → only then `PRAGMA foreign_keys=ON`, `journal_mode=WAL`,
`synchronous=FULL`, `busy_timeout` → apply each pending migration in its own
`IMMEDIATE` transaction together with its ledger row and `PRAGMA user_version`.

## Work packages

```text
WP1 storage crate: worker, migrations, interface, unit tests ─┬─> WP2 tests/storage acceptance + E2E, xtask member
                                                              └─> WP3 ordo storage-lab example + GPUI harness test
```

### WP1 — Storage Module (`crates/storage/**`, `migrations/**`, root `Cargo.toml` `[workspace.dependencies]` only, `deny.toml` if needed)

- `src/lib.rs` (interface + errors), `src/worker.rs`, `src/migrations/mod.rs`
  (runner, `include_str!` of `migrations/000N_*.sql`, ledger table
  `ordo_migrations(id INTEGER PRIMARY KEY, name TEXT NOT NULL, checksum TEXT NOT
  NULL, applied_at TEXT NOT NULL)`).
- Unit tests in-crate for the runner (ordering, checksum, rollback) using
  `tempfile`-free temp dirs under `std::env::temp_dir()` with a unique name.

### WP2 — Acceptance harness (`tests/storage/**`, root `Cargo.toml` `members`, `xtask/src/lib.rs`)

- New `storage-tests` package, dev-deps only (`storage` with
  `fault-injection`, `futures-lite`), registered in workspace members, xtask
  expected members, and the edge contract with no internal deps.
- One test per AC bullet plus the E2E: fresh → head; re-run no-op (ledger
  unchanged); broken next migration → schema, data, ledger stay at last valid
  version; newer schema (ledger row id 999 written by raw `rusqlite` dev-dep in
  the test only) refused and file bytes unchanged; FK violation rejected; WAL
  mode reported; busy (second raw connection holds an exclusive lock) → `Busy`;
  100 concurrent requests from 8 threads serialized with a deterministic final
  count; panic / closed channel / shutdown each give structured results within a
  timeout.

### WP3 — Manual review path (`crates/ordo/Cargo.toml`, `crates/ordo/examples/storage-lab.rs`, `crates/ordo/tests/storage_supervision.rs`)

- `storage-lab`: GPUI window that spawns `Storage` on a temp DB, shows schema
  status, journal mode, FK flag, parish name, note count; buttons "Add note",
  "Rename parish", "Shutdown". All awaits run off the GPUI thread via
  `cx.spawn`; the UI stays responsive.
- `storage_supervision.rs`: GPUI `TestAppContext` test awaiting a panic,
  closed channel, and shutdown through the app executor without hanging.
