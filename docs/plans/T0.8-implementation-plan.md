# T0.8 implementation plan

> Active plan. `MILESTONES.md` owns T0.8's status and acceptance gates; this
> file owns only the order in which the work lands. Freeze it at the gate close.

## Outcome

Freeze the portable contract shape: seven versioned JSON Schemas under
`contracts/`, a fixture corpus per schema, and a development-only
`tools/artifact-container-spike` crate that creates, inspects, safely stages,
validates, and routes universal `.ordo` ZIP containers. One PR from three work
packages, each ending in `cargo xtask verify`.

Constraints that shape the split:

- **Spike, not production.** MVP-PLAN §6.4: Phase 0 container work lives in a
  `tools/*-spike` package. Package name `artifact-container-spike`; no
  production crate depends on it. xtask's member list and dependency contract
  gain `artifact-container-spike` (no internal deps) and
  `artifact-container-tests` (dev-dep only, empty internal set).
- **No GPUI, no SQLite.** The spike touches only `std`, `serde`, `serde_json`,
  `sha2` (locked), `zip` (new, exact pin `=2.4.2`, `default-features = false,
  features = ["deflate"]`), and `uuid` (locked) for IDs in fixtures only.
- **Schemas are data.** JSON Schema draft 2020-12 files in
  `contracts/<kind>/v1.schema.json`. The spike does not pull a JSON Schema
  engine; it implements a typed serde validator per kind that mirrors the
  schema, and a test asserts every schema file parses, declares `$id`,
  `$schema`, `schema_version` const 1, and the required keys the validator
  enforces (drift guard).
- **Kinds and versions.** Container kinds: `song-import`, `liturgy-import`,
  `celebration-package`, `parish-backup`, `diagnostic-report`. Non-container
  contracts: `snapshot-manifest` (embedded in Celebration Package/Backup
  payloads) and `recovery-journal` (local file). Every contract carries
  `schema_version: 1` and stable `id` (UUID string).
- **Manifest.** `manifest.json` = `{ format: "ordo-container", format_version: 1,
  kind, schema_version, artifact_id, created_at, payload: { path:
  "payload.json", sha256, size }, assets: [{ path: "assets/…", sha256, size }] }`.
- **Limits** (constants, overridable in `InspectLimits` for tests): archive
  64 MiB for every kind (owner, 2026-10-10: Parish Backups temporarily capped at 64 MiB too; revisit when needed), 4096 entries, per-entry and total
  uncompressed ceilings, compression ratio ≤ 200, path rules (no absolute,
  no `..`, no backslash, no drive prefix, no NUL, NFC-normalised duplicate
  check case-insensitively), symlink/non-regular entries rejected, unlisted
  entries rejected, listed-but-missing rejected.
- **Outcome taxonomy.** `Inspection::Valid(Routed)`, `Invalid(Vec<Failure>)`,
  `Unsupported { kind, version, supported }` (compatible-version message).
  `NeedsDecision` exists in the type but is never produced by the container
  layer — it is the reconciliation layer's (distinct from Invalid by type).
- **Staging.** Inspection extracts only into a caller-provided staging dir
  (tests use `tempfile`), writes nothing elsewhere, and never receives a Parish
  handle — "no Parish mutation" is structural: the API has no parish argument.
- **Atomic creation.** `create(dest, kind, payload, assets)` writes
  `.<name>.ordo.tmp-<pid>-<n>` beside `dest`, fsyncs, reopens with `inspect`,
  then `std::fs::rename` (atomic replace on NTFS via MoveFileEx semantics);
  on any failure the temp is removed and an existing `dest` is untouched.
- **Manual review.** No GPUI surface yet owns portability; the owner exercises
  the spike via its CLI: `cargo run -p artifact-container-spike -- create
  song-import contracts/song-import/examples/minimal.json out.ordo` then
  `-- inspect out.ordo`.

## Interface (fixed by WP1)

```rust
pub enum ArtifactKind { SongImport, LiturgyImport, CelebrationPackage, ParishBackup, DiagnosticReport }
pub struct InspectLimits { max_archive: u64, max_entries: usize, max_entry: u64, max_total: u64, max_ratio: u64 }
pub enum Inspection { Valid(Routed), Invalid(Vec<Failure>), Unsupported { kind: String, version: u64, supported: &'static [u64] } }
pub struct Routed { pub kind: ArtifactKind, pub manifest: Manifest, pub payload: serde_json::Value, pub staged_assets: Vec<PathBuf> }
pub enum Failure { ArchiveTooLarge, TooManyEntries, EntryTooLarge{..}, RatioExceeded{..}, UnsafePath{..}, DuplicatePath{..}, Link{..}, MissingManifest, BadManifest(String), Unlisted{..}, Missing{..}, Checksum{..}, Payload(Vec<ContractError>) }
pub fn inspect(archive: &Path, staging: &Path, limits: &InspectLimits) -> Inspection;
pub fn create(dest: &Path, kind: ArtifactKind, payload: &serde_json::Value, assets: &[(String, Vec<u8>)]) -> Result<Manifest, CreateError>;
pub fn validate_contract(contract: Contract, doc: &serde_json::Value) -> Result<(), Vec<ContractError>>; // all 7
```

## Deviations

- **NFC normalisation gap.** The duplicate check folds case only (`to_lowercase`).
  It does not normalise to NFC, because the workspace has no normalisation crate.
  Two names that differ only in Unicode normalisation form are not caught as
  duplicates.
- **`uuid` is a normal dependency.** The plan limited `uuid` to fixtures. `create`
  now uses `uuid` v4 to assign `artifact_id`, so it is a normal dependency.
- **Parish Backups capped at 64 MiB.** Owner decision, 2026-10-10: every kind,
  Parish Backups included, is capped at 64 MiB for now. There is no backup-specific
  limit. Revisit when needed.
- **Duplicate detection.** The zip crate (2.4.2) keys entries by name, so
  exact-duplicate names collapse. Inspection reads the raw End Of Central Directory
  count (ZIP64 when declared) before opening the reader, applies `max_entries` to
  that raw count, and refuses any archive whose raw count differs from the reader's
  unique count with `Failure::EntryCountMismatch { declared, unique }`. Case-only
  duplicates are still reported as `DuplicatePath`.
- **Interface additions.** `InspectLimits` gains `max_payload` (64 MiB, applied to
  `manifest.json` and `payload.json` as `EntryTooLarge`). `Failure` gains
  `EntryCountMismatch`. Windows device names and segments ending in a dot or space
  are refused as `UnsafePath`. A non-empty staging directory is refused as
  `Unreadable`.
- **Entry type from attributes.** `ZipFile::unix_mode()` (zip 2.4.2) maps the
  MS-DOS directory bit (`0x10`) to `S_IFDIR` and returns Unix modes as stored,
  so inspection refuses a directory-flagged entry without a trailing slash, and
  any symlink, without parsing headers itself. `is_dir()` is name-only and is
  not used for this.
- **Format version.** A `format_version` above 1 is `Unsupported` (kind
  `container`), not a bad manifest. Zero, non-integer, or missing values stay bad
  manifests. `docs/contracts/README.md` section 5 says the same.
