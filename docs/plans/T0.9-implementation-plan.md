## Outcome

Prove the emergency-deck contract (Decisions 15, 52, 53; MVP-PLAN emergency
`.pptx`) with a development-only `tools/powerpoint-spike` crate that writes a
static-image `.pptx`, reopens and validates it, and publishes it atomically. An
independent `cargo xtask inspect-pptx <file>` re-reads any deck without sharing
the generator's code.

Constraints that shape the split:

- **Chosen library: none beyond ZIP + PNG.** No maintained Rust `.pptx` writer
  covers sections and notes. The spike writes the OOXML parts by hand
  (PresentationML, ECMA-376 transitional) into a ZIP using the already pinned
  `zip =2.4.2` (deflate). PNG encode/decode uses `png =0.18.1` (already in
  `Cargo.lock`). XML is emitted with escaped `format!` templates and read back
  with `quick-xml =0.41.0` (already in `Cargo.lock`). `sha2 =0.10.9` for hashes.
  Isolating this behind one Seam is MVP-PLAN's stated intent: the format tooling
  may change, validation runs on the artifact.
- **Spike, not production.** MVP-PLAN §6.4: package `powerpoint-spike`, empty
  internal dependency set; `powerpoint-tests` (tests/powerpoint) likewise.
  xtask's member list and dependency contract gain both.
- **Frames.** The spike does not call the canonical renderer (no GPUI in a
  spike; the production `powerpoint` crate will consume snapshot frames). Its
  input is a `DeckPlan` of already-rendered 1920x1080 RGB(A) PNG bytes. Fixture
  frames are generated deterministically by the test (solid fields plus a
  per-cue stripe pattern) so hashes are stable without binary fixtures in git.
  Any frame that is not exactly 1920x1080 is a generation error.
- **Deck shape.**
  - Slide size `12192000 x 6858000` EMU (16:9). Each image slide is one
    `p:pic` at offset 0,0 with extent equal to the slide: full bleed, no text
    boxes, no placeholders, `noChangeAspect`.
  - Operator-only Cues (Hold, Blackout, private cue text) become a slide with a
    black background and no shapes; their text goes to the notes slide.
  - Slide 1 is a black lead-in in section `Safety`, notes `Safety lead-in:
    black slide before the first Mass item.`; the last slide is a black closing
    in a second section `Safety`, notes `Safety closing: black slide after the
    final Mass item.`
  - Between them one `p14:section` per top-level Mass item, in order, named
    after the item, listing its slide ids (`p:extLst` /
    `{521415D9-36F7-43E2-AB2F-B90AF26B5E84}` / `p14:sectionLst`).
  - Notes slides exist only for operator-only and safety slides; congregation
    image slides have none. Notes master + notes slide parts per ECMA-376.
  - One slide master, one blank layout, minimal theme. `docProps/app.xml`,
    `docProps/core.xml`, `[Content_Types].xml`, `_rels/.rels`.
  - Media named `ppt/media/imageN.png`, one per image slide (no dedup, so
    order checks map 1:1).
- **Validation (spike, `validate`).** Reopen the finished ZIP and check against
  the `DeckPlan`: slide count and order, section names and membership, each
  image's PNG header is 1920x1080 and its SHA-256 equals the input frame,
  image `p:pic` extent equals slide size and there are no `p:sp` text shapes on
  image slides, operator-only/safety slides have black `p:bg` and the expected
  notes text, congregation slides have no notes.
- **Atomic publication.** `export(dest, plan)` writes
  `.<name>.pptx.tmp-<pid>-<n>` beside `dest`, fsyncs, runs `validate`, then
  `std::fs::rename`. On any failure the temp is removed, `dest` is untouched,
  and the error names the failing check (and Cue index when relevant).
- **xtask inspector.** `xtask/src/inspect_pptx.rs` reads a deck, prints slide
  order with section, kind (image WxH + sha256 prefix / black), and notes, and
  exits non-zero if structural rules fail (16:9, full bleed, safety first/last,
  every slide in exactly one section, notes only on black slides). xtask gains
  `zip` (workspace) and `png`, `quick-xml` exact pins. Not part of `verify`.
- **Manual review.** `cargo run -p powerpoint-spike -- fixture <out.pptx>`
  writes the E2E fixture deck; `cargo xtask inspect-pptx <out.pptx>` prints it;
  the owner opens it in PowerPoint (and later on the church PC: `[MANUAL]`).

## Interface (fixed by this plan)

```rust
pub struct DeckPlan { pub items: Vec<MassItem> }
pub struct MassItem { pub title: String, pub cues: Vec<Cue> }
pub enum Cue { Image { png: Vec<u8> }, OperatorOnly { notes: String } }
pub enum ExportError { BadFrame { item: usize, cue: usize, reason: String }, Io(std::io::Error), Validation(Vec<String>) }
pub fn build(plan: &DeckPlan) -> Result<Vec<u8>, ExportError>;              // whole .pptx bytes
pub fn validate(pptx: &[u8], plan: &DeckPlan) -> Result<(), Vec<String>>;
pub fn export(dest: &Path, plan: &DeckPlan) -> Result<(), ExportError>;     // temp -> validate -> rename
pub fn fixture_plan() -> DeckPlan; // identification, lyrics, response, reading, Hold, Blackout
```

## Work packages

```
WP1 (spike crate + xtask wiring) ─┐
WP2 (xtask inspect-pptx)  ────────┴─► WP3 (tests/powerpoint E2E + fixtures)
```

WP1 and WP2 run in parallel against the deck shape above; WP3 starts after both
merge.

| WP | Owns (exclusive) | Serves |
|----|------------------|--------|
| WP1 | `tools/powerpoint-spike/**`, root `Cargo.toml`, `Cargo.lock`, `xtask/src/lib.rs` (members + contract only) | AC1, AC2, AC3, AC4 |
| WP2 | `xtask/src/inspect_pptx.rs`, `xtask/src/main.rs`, `xtask/Cargo.toml` (root `Cargo.lock` edits merged by me) | AC3, E2E inspection |
| WP3 | `tests/powerpoint/**`, `tests/fixtures/powerpoint/**`, `tests/README.md`, root `Cargo.toml` members line | E2E, AC3, AC4 |

`tests/fixtures/powerpoint/` holds `fixture-plan.json` (titles, cue kinds,
notes, frame seeds) and `expected-outline.txt` (the inspector's expected slide
listing), not binaries.
