# T1.7 implementation plan

## Outcome

If Ordo is killed mid-presentation, the next launch goes straight back into
Presenter with the congregation display black. There is no dialog. The
operator finds Preview where it was and sees a persistent strip,
**Presentation recovered · Congregation output is black**. What Program showed
before is visible only as private context. One deliberate `Space` on a valid
Preview takes it live and clears the strip. **Exit Presenter** still ends an
obsolete session safely.

A session journal makes this possible. Every Engine change writes a compact
record off the GPUI thread: snapshot identity, Preview, the last valid Program,
the live state, output evidence and a sequence number. The latest record wins.
A record that is torn, stale, of an unknown version or from a different
snapshot is rejected, and Ordo opens normally instead of guessing.

Sources:
- Decision 14: what is journaled and restored.
- Decision 228: non-modal, fail-closed reopening and the strip text.
- Decision 311: recovery keys on SnapshotId + CueId, and the move to
  `recovery-journal` v2.
- `docs/mockups/presenter-faults.html` states G and H.

## Shaping constraints (verified)

- **v1 is the wrong shape.** `contracts/recovery-journal/v1.schema.json` is an
  append-only action log (`cue`, `freeze`, `blackout`, …) keyed by a flat
  `cue_index`. It has no separate Preview and Program, no output evidence and
  no snapshot hash, and replaying it would mean re-running Engine commands.
  Decision 311 already schedules the move to `cue_id` as v2 "when recovery is
  implemented". v1 stays frozen, and v2 is a new schema.
- **Snapshot identity.** `LoadedSnapshot` exposes `manifest_hash()` (SHA-256
  of the exact manifest bytes) and the snapshot's `id()` (`SnapshotId`). Equal
  content can have different bytes (Decision 311), so recovery matches **both**
  the id and the hash.
- **Cue identity.** `Cue::id()` gives a `CueId`. The Engine works in flat
  indexes (`EngineState::preview()`, `ProgramContent::Frame { cue }`), so the
  journal maps index → `CueId` on write and `CueId` → index on read. An unknown
  `CueId` means a mismatched snapshot.
- **Engine.** `Engine::new(snapshot)` always starts `OutputDisabled`. Recovery
  needs a second constructor that starts from a validated recovery point.
  `revision` already increases on every change, so the journal sequence can be
  the Engine revision plus a session epoch, with no new counter on the hot
  path.
- **Workers.** `RuntimeWorkers` (`crates/ordo/src/lib.rs:319`) already runs an
  owned Storage worker fed by an `mpsc` channel for preferences.
  `crates/ordo/tests/hot_path_blocking.rs` fails on any unreviewed blocking
  call. The journal writer follows the same pattern: the GPUI thread only does
  a non-blocking `send` of a small `Copy`/owned record.
- **Session hooks.** T1.6a's `SessionHooks { close_output, on_session_ended }`
  (`presenter/session_header/exit.rs`) is the seam for a clean end. #132's quit
  confirmation runs `close_output_safely` and must end the session too.
- **Display evidence.** `DisplayEvidence { name, uuid, bounds }` and
  `recognize()` (T1.6c/d) decide whether a returning display is "the same".
  The journal stores the assigned display's evidence, so recovery can reuse
  `recognize()` unchanged.
- **Snapshot source.** Presenter currently opens only the `normal-mass`
  fixture through `fixture_snapshot_dir()` (`CARGO_MANIFEST_DIR`). The title
  says "fixture-session": in T1.7 the journal records the snapshot
  **directory**, and recovery reloads from it and then checks identity. Real
  Mass-plan sources come later and need no format change.
- **Dependencies.**
  - `uuid` gains the `v4` feature for `session_id`. `getrandom` is already in
    `Cargo.lock`, so check that `cargo deny` accepts the feature.
  - `serde`/`serde_json` are already pinned in `presentation`.
  - No new crate.

## Work packages

### WP1 — Decision: compact recovery journal v2 (T1.7a) · mechanical

AC1, AC3. It only writes down what the constraints above and the owner's
answers to the open questions settle.

- New decision `docs/decisions/0314-compact-recovery-journal-v2.md`. It amends
  Decision 14 and records the v2 shape and rules:
  - **Compact state, not a log.** The latest record replaces the previous one.
  - **Atomic replace.** Write a temp file, flush, rename over
    `session-recovery.json` beside the installation preferences file.
  - **Rejection rules.** Torn, stale, unknown version and mismatched snapshot
    are each rejected, and none of them is guessed around.
  - **Clean end.** A clean end deletes the journal.
- Regenerate the decision index (`python docs/decisions/adr.py index`, then
  `check`).

### WP2 — `recovery-journal` v2 contract and codec (T1.7a) · design-sensitive

AC1, AC3. This defines an on-disk safety format and its rejection rules.

- `contracts/recovery-journal/v2.schema.json` with an example under
  `examples/`, plus `docs/contracts/README.md` (§5 versioning, §6 rules
  table). Fields:
  - `schema_version: 2`, `session_id` (UUIDv4), `seq` (u64, strictly
    increasing within a session), `written_at` (UTC);
  - `snapshot { id, manifest_hash, source_dir }`;
  - `preview { cue_id }`;
  - `program`: `{ cue_id }` or `null` for black, the last **valid** Program
    context;
  - `state`: one of `output-disabled`, `enabled-black`, `live`, `frozen`,
    `blackout`, `disconnected`;
  - `output { enabled, display: { name?, uuid?, bounds } | null }`;
  - `ended` (bool): true only on a clean end, for the stale rule;
  - `record_sha256`: SHA-256 of the canonical record without that field, which
    catches tearing.
- `crates/presentation/src/journal/` (new, pure, no I/O):
  - `RecoveryPoint`, the typed record;
  - `encode(&RecoveryPoint) -> Vec<u8>`;
  - `decode(&[u8]) -> Result<RecoveryPoint, JournalRejection>`;
  - `validate(point, &LoadedSnapshot) -> Result<ValidatedRecovery, JournalRejection>`.
- `JournalRejection::{Torn, UnknownVersion(u32), Stale, SnapshotMismatch,
  UnknownCue}`. Each one is a typed reason that later goes to Diagnostics.
- Tests, one per rejection:
  - truncated bytes, flipped bytes and a bad hash are `Torn`;
  - `schema_version` 1 or 3 is `UnknownVersion`;
  - a different hash or snapshot id is `SnapshotMismatch`;
  - a removed cue is `UnknownCue`;
  - `ended: true` is `Stale`, whatever its age.
- A round-trip test, plus a test that the example in `contracts/` decodes.
- xtask's contract validation picks up v2. Check how v1 is wired.

### WP3 — Recovery point from Engine state (T1.7b) · mechanical

AC1. `presentation::journal::RecoveryPoint::from_engine(&Engine, output: &OutputEvidence)`.

- It maps the flat indexes to `CueId`s, and `LiveState` to `state`.
  `Disconnected` keeps `output.enabled = true`.
- `program` is the last **valid** Program: `ProgramContent::Frame`'s cue. When
  Program is black from Blackout or a Hold, it keeps the cue that was on
  Program before, so the private context can still name it. When nothing was
  ever live, it is `null`.
- Unit tests over `test_support` snapshots for each `LiveState`.

### WP4 — Asynchronous ordered writer (T1.7b) · design-sensitive

AC2. Concurrency, ordering and the hot path are all involved.

- `crates/ordo/src/recovery.rs` (new): `JournalWriter`, owned by
  `RuntimeWorkers` as one more named `OwnedWorker` with shutdown, so the
  long-lived task has an owner.
  - **The GPUI thread** only calls `writer.record(point)`, a non-blocking
    `send`.
  - **The worker** drains the channel to the newest point (coalescing, so a
    burst of Next presses is one write), encodes it, writes the temp file,
    flushes and renames.
  - **Ordering:** a point whose `seq` is not greater than the last written one
    is dropped.
  - `end_session()` first writes `ended: true`, then deletes the file. Both
    are ordered after any pending write.
- The Presenter calls `record` after each accepted Engine command or output
  change, through a new `SessionHooks::journal` hook, so the Presenter stays
  free of file and storage code. The lab and tests get a no-op hook.
- `SessionHooks::on_session_ended` and #132's quit path call `end_session()`.
- Tests:
  - writes land in order, and a burst coalesces to the last point;
  - `end_session` after pending writes leaves no file;
  - a write failure is reported and never panics;
  - all of them use temp directories.
- `hot_path_blocking.rs`: the worker's blocking `recv` is listed as a
  reviewed worker-thread site. The performance gate (`presenter-lab` bench)
  shows no regression in keydown-to-paint p95.

### WP5 — Engine recovery (T1.7c) · design-sensitive

AC4 to AC6 at the Engine level. A new entry state for the safety state
machine.

- `Engine::recover(snapshot, ValidatedRecovery, display_recognized: bool) -> Engine`:
  - **Preview** is the journaled cue.
  - **Program** is always `Black`.
  - **Live state:**
    - `OutputDisabled` if output had been disabled;
    - `EnabledBlack` if output was enabled and its display is recognized;
    - otherwise `Disconnected { display_back: false }`.
  - `recovered() -> Option<PriorProgram { cue, state }>` holds the private
    context: the last valid Program cue and the interrupted state (Live,
    Frozen or Blackout).
- `Take` on a valid Preview goes Live linked, as from `EnabledBlack`, and
  clears `recovered`. A refused `Take` (Preview unavailable) keeps it. Other
  navigation keeps it.
- `DisableOutput` and the exit path also clear it. That is the ordinary safe
  exit.
- Frozen and Blackout intent is restored only as the private label in
  `PriorProgram`. Space always resumes the ordinary linked state (Decision 14).
- Tests for every interrupted state × output enabled, disabled or
  unrecognized: the resulting `LiveState`, Program black, Preview, then `Take`.

### WP6 — Startup reopens into recovered Presenter (T1.7d) · GPUI-facing

AC4.

- `crates/ordo/src/recovery.rs`: at runtime start, the Storage worker reads
  `session-recovery.json` off the GPUI thread. It decodes the file, loads the
  snapshot from `source_dir`, and runs `validate`. The result goes back over a
  channel, as preferences restore does today.
- **Valid:** the shell enters Presenter directly (no Preparation frame first,
  no dialog), through the same entry path as T1.6a, with
  `Engine::recover(...)`.
  - If output had been enabled and the journaled display evidence is
    recognized among the current displays, the congregation window opens
    black.
  - If it is not recognized, the Presenter shows Disconnected and nothing
    moves.
- **Rejected or absent:** Ordo opens Preparation as today. A rejected journal
  is renamed to `session-recovery.rejected.json`, so Diagnostics can show it
  later and it is never retried, and the rejection is logged.
- Tests use temp directories, the in-memory display adapter and journal files
  written by WP2's encoder.

### WP7 — Recovery strip and private Program context (T1.7d) · GPUI-facing

AC4, AC5.

- **Strip.** A persistent operator-chrome strip under the session header,
  `role=status`, info state, following `presenter-faults.html` state G:
  - **Presentation recovered · Congregation output is black**;
  - the detail line, "Ordo closed unexpectedly at <time>. Your place is back.
    Space takes Preview live." When the display is not recognized: "<Display>
    wasn't recognized, so output is disconnected."
  - The strip is not dismissable by click. Space (a successful Take) and exit
    clear it.
- **Private context.** The strip's right side shows "Before the interruption":
  a mini frame of the prior Program cue, then "<STATE> on <item> · <n.m> · not
  on screen now". The Program monitor itself shows black or Disconnected, as
  the Engine says, and never the prior frame.
- **Boundary.** The congregation-boundary scan in `output_tests` adds the
  strip selectors to `OPERATOR_ONLY`.
- Tests:
  - the strip appears, then clears after Space;
  - the Program monitor is black while the prior frame is in the strip only;
  - exit from the recovered state takes the normal path.

### WP8 — E2E, ticks, freeze (T1.7e) · design-sensitive

The E2E line. Freezes the plan.

- Recovery E2E in `crates/ordo/src/shell/tests/recovery_e2e.rs`, following
  the T1.6 E2E layout. For each of **Live**, **Frozen** and **Blackout**:
  1. drive a real session with the in-memory projector and let the writer
     journal it;
  2. drop the runtime without a clean end (simulated termination);
  3. start a fresh shell on the same temp directory;
  4. assert the restored operator context is identical (Preview, prior
     Program cue and state, output evidence);
  5. assert the external Program stays black: the output window's drawn frame
     is black;
  6. assert one `Space` takes Preview live and clears the strip, and that
     nothing went live before it.
- A killed **process** is not needed. The journal is the only state that
  survives, so dropping without `end_session` is the same input. Note this in
  the module doc.
- Tick only the evidenced `[AUTO]`/`[UI-AUTO]` rows in `MILESTONES.md`, then
  freeze this plan.
- PR body: manual steps. Kill `ordo.exe` from Task Manager while Live, then
  relaunch on the dev PC with the external display.

## Risks

- **Write amplification while navigating fast.** Coalescing on the worker
  keeps it to roughly one write per burst. Flush and rename cost lands only on
  the worker.
- **Antivirus or indexer holding the temp file on Windows** can make the
  rename fail. Retry once, then report. The previous good record stays valid
  in the meantime.
- **Clock-free sequence.** `seq` comes from the Engine revision within a
  `session_id`, so wall-clock changes never reorder records.
- **The fixture path again.** On the church PC the snapshot source directory
  differs from the dev build's (T1.6 risk). Recovery reloads from the
  journaled `source_dir` and rejects on mismatch, so it fails closed. It does
  not reopen the wrong Mass.
- **Emergency inserts and overrides** (Decision 14) do not exist yet. v2
  leaves room for them in a later version, and T1.7 does not invent them.

## Owner decisions (2026-11-07)

1. **Stale** means the session ended cleanly: a record with `ended: true`, left
   behind when a crash falls between the end and the delete. Age alone never
   makes a journal stale. An old interrupted session still reopens and ends
   through Exit Presenter (Decision 228).
2. **A rejected journal** is kept once as `session-recovery.rejected.json` for
   Diagnostics. It is never retried, and the rejection is logged.
3. **Space after a Frozen or Blackout crash** resumes the ordinary linked Live
   state (Decision 14). The interrupted state shows only as the private label
   ("FROZEN on Gloria · not on screen now"), and the operator presses F or B
   again if wanted.
