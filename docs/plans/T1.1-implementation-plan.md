# T1.1 implementation plan

> Active plan. `MILESTONES.md` owns T1.1's status and acceptance gates; this
> file owns only the order in which the work lands. Freeze it at the gate close.

## Outcome

Give the Presenter one immutable, realistic input contract independent of
planning and persistence: a pure domain model of a Presentation snapshot
(Mass sections → Mass items → Cues), a snapshot reader that validates every
frame and asset dependency before exposing a usable input, and two sanitized
fixtures (**Normal Mass**, **Recovery Drill**). Two stacked micro-PRs:

| PR | Branch | Work packages |
|---|---|---|
| T1.1a | `t1.1a-presentation-cue-model` | WP1 domain model |
| T1.1b | `t1.1b-snapshot-reader-fixtures` | WP2 reader, WP3 fixtures + E2E |

## Shaping constraints

- **Domain stays pure.** `crates/domain/src/presentation.rs` has no
  dependency at all (domain's `[dependencies]` stays empty): no GPUI, no
  filesystem, no hashing crate. IDs and digests are plain value types parsed
  from text. Invariants live in constructors, so an invalid snapshot cannot
  exist as a value.
- **Sections own no Cue.** `MassSection` holds `items: Vec<MassItem>` and
  nothing projectable; every `Cue` lives in exactly one `MassItem.cues`. A
  Cue ID appearing twice anywhere in a snapshot is a construction error, so
  "exactly one Mass item" is structural plus checked.
- **Cue behaviour is a closed enum** whose Program effect is derived, never
  stored separately:

  | `CueBehavior` | Program effect | Private context |
  |---|---|---|
  | `Project { frame, duration }` | that complete frame | optional |
  | `OperatorTrigger` | black | required (the trigger phrase) |
  | `Hold` | black | optional |
  | `Wait` | unchanged | required (what happens meanwhile) |
  | `Unavailable { reason }` | none: never live | optional |

  Blackout is a presentation *state* (CONTEXT.md), not a Cue; the Recovery
  Drill covers it through its command script, which T1.2 replays.
- **Unavailable vs missing.** An `Unavailable` Cue is captured content that
  could not be produced faithfully; the snapshot still loads. A *declared*
  frame or asset that is missing, unreadable, or hash-mismatched is a
  dependency failure: the whole load fails and no usable input is exposed.
- **Themes.** "Both Themes" = one parish custom Theme and the guaranteed
  built-in fallback Theme (Decision 22). A snapshot lists its Themes, names its
  Mass Theme, and an item may override it; every reference must resolve.
- **Auto-play metadata.** Only `GeneralPresentation` items may carry
  `AutoPlay { default_seconds }` (MVP-PLAN §8.4, eight seconds by default);
  their projectable Cues may override the duration. Other items carrying
  auto-play, or a duration on a Cue outside an auto-play item, are errors.
- **Fixture format is a Phase-1 input contract, not `snapshot-manifest` v1.**
  The frozen T0.8 JSON contract has no sections or Cues yet. The fixtures use
  a line format in the spirit of `ordo-fixture/1`, needing no parser crate.
  Reconciling it into the portable contract belongs to the Snapshot and
  Portability Module (later phase). Flagged for owner confirmation.
- **Frames are template content.** Each frame file is exactly the
  `ordo-fixture/1` format the golden harness reads
  (`crates/rendering/tests/golden.rs`), parsed by a production parser in
  `presentation` and validated by `rendering::render_template` succeeding.
  T0.6 adopted the retained path, so no raster is part of the snapshot.
- **Hashes.** SHA-256 of the exact bytes (`sha2 =0.10.9`, already locked;
  a new edge on `presentation` only). The snapshot fingerprint is the SHA-256
  of every frame and asset `sha256` hex, sorted, each followed by LF (same
  rule as `assets_fingerprint` in `snapshot-manifest` v1).
- **Reader I/O seam.** The reader takes a `SnapshotSource` trait (read bytes
  by relative path) with a `DirectorySource` implementation, so tests and the
  later container layer can feed it without touching the GPUI thread.

## Interface (fixed by WP1)

```rust
// crates/domain/src/presentation.rs
pub struct EntityId([u8; 16]);           // parse("xxxxxxxx-xxxx-4xxx-[89ab]xxx-xxxxxxxxxxxx"), Display lowercase
// typed newtypes over EntityId: SnapshotId, MassSectionId, MassItemId, CueId, ThemeId, FrameId, AssetId
pub struct ContentHash([u8; 32]);        // parse 64 lowercase hex, Display
pub enum ThemeKind { Custom, Fallback }
pub struct ThemeRef { pub id: ThemeId, pub name: String, pub kind: ThemeKind }
pub enum MassItemKind { Song, Reading, Psalm, ResponseSequence, GeneralPresentation, Rite }
pub struct AutoPlay { pub default_seconds: u32 }          // > 0
pub enum CueBehavior { Project { frame: FrameId, duration_seconds: Option<u32> }, OperatorTrigger, Hold, Wait, Unavailable { reason: String } }
pub enum ProgramEffect { Frame(FrameId), Black, Unchanged, NotPresentable }
pub struct Cue { id, label: String, private_context: Option<String>, behavior: CueBehavior }
pub struct MassItem { id, title, kind, theme_override: Option<ThemeId>, auto_play: Option<AutoPlay>, cues: Vec<Cue> }
pub struct MassSection { id, title, items: Vec<MassItem> }
pub struct PresentationSnapshot { id, title, mass_theme: ThemeId, themes: Vec<ThemeRef>, sections: Vec<MassSection> }
impl PresentationSnapshot {
    pub fn new(...) -> Result<Self, SnapshotError>;
    pub fn positions(&self) -> Vec<CuePosition>;   // flattened Mass-item/Cue order
    pub fn cue(&self, flat: usize) -> Option<&Cue>;
    pub fn frame_ids(&self) -> BTreeSet<FrameId>;
    pub fn effective_theme(&self, item: &MassItem) -> &ThemeRef;
}
pub struct CuePosition { pub flat: usize, pub section: usize, pub item: usize, pub cue: usize, pub cue_id: CueId, pub item_id: MassItemId }
```

## Work packages

### WP1 — Domain Presentation model *(design-sensitive: new invariants)*

AC 3, AC 4 (model half). Files: `crates/domain/src/presentation.rs` (new),
`crates/domain/src/lib.rs` (module + doc line). Unit tests in the module:
ID/hash parse round-trips and rejections; duplicate IDs across sections,
items and Cues rejected; empty section/item rejected; unresolved Theme
rejected; auto-play on a non-General item and stray durations rejected;
`program_effect()` per behaviour; OperatorTrigger/Wait without private context
rejected; `positions()` order and indices.

### WP2 — Snapshot reader *(design-sensitive: validation boundary)*

AC 5. Files: `crates/presentation/src/snapshot_reader.rs` (new),
`crates/presentation/src/lib.rs` (module), `crates/presentation/Cargo.toml`
(`sha2 = "=0.10.9"`). `read_snapshot(&dyn SnapshotSource) ->
Result<LoadedSnapshot, SnapshotLoadError>`; `LoadedSnapshot` exposes the
domain snapshot, `frame(FrameId) -> &TemplateContent`, every frame/asset
hash, and the fingerprint. Load order: parse manifest → build domain
snapshot → every declared frame and asset read, hashed, compared → every
frame parsed and rendered once with `render_template` → fingerprint
recomputed and compared → every `Project` Cue's frame declared and every
declared frame used, every GeneralImage image id a declared asset. Any
failure returns a typed error naming the path/ID; nothing partial escapes.

### WP3 — Fixtures and E2E *(mechanical: format and API fixed above)*

AC 1, AC 2, E2E. Files: `tests/fixtures/presentations/{normal-mass,recovery-drill}/`
(`snapshot.txt`, `frames/*.txt`, `assets/*`), `tests/presentation/tests/snapshot.rs`,
`tests/presentation/Cargo.toml` (`tempfile` dev-dep),
`crates/presentation/examples/snapshot-inspect.rs`. Sanitized content only
(no parish names, no copyrighted lyrics: original placeholder verse).

## Manual review

`cargo run -p presentation --example snapshot-inspect -- tests/fixtures/presentations/normal-mass`
prints the flattened section/item/Cue order, each Cue's Program effect and
private context, and the fingerprint; pointing it at a copy with a deleted
frame prints the rejection.
