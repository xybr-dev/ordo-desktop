## Outcome

T2.3 delivers the complete MVP Song Library model as pure domain behavior, with no UI and no storage. It is one Module Interface, `domain::song_library::SongLibrary`, with these properties:

- It owns Song works, Arrangements and Choirs, and enforces their invariants.
- The primary title is the only requirement to create a Song work. Authored text is kept verbatim.
- An Arrangement belongs to one Song and independently owns these:
  - its title, languages, Choir associations, rendition attribution and applicability;
  - its sections, Sequence, pagination state and archive state.
- Multiple Choirs may share one Arrangement. Songs and Arrangements stay valid with no Choir.
- Archival is non-cascading and reversible. An archived Song suppresses its Arrangements from ordinary selection but never rewrites their own archive state.
- Permanent deletion goes through one reference-safety check and never cascades.
- Duplicate evidence compares normalized, case-insensitive titles and aliases. It only reports; it never rewrites authored capitalization or unites entities.
- The Interface offers no merge and no redirect.

## Shaping constraints (verified)

- **`domain` stays pure.** It has no I/O, clock or randomness. Callers pass in ids (the typed ids in `domain::identity`) and `Timestamp`s, as T2.2 does.
- **Aggregate in memory.** `SongLibrary` is an in-memory aggregate (`BTreeMap`s keyed by typed id). A Parish holds hundreds of Songs, not millions. T2.4 hydrates it from storage and persists accepted changes through the storage Interface. The storage schema already has `archived_at` on song, arrangement and choir. Pagination state has no column yet; T2.4 adds it with the first screen that shows it.
- **Edits.** Content edits validate here. Their durable revisions remain T2.2's job (storage `commit_*_edit`); T2.3 does not touch storage.
- **Selection eligibility** is an Arrangement that is itself active and whose Song is active. **Visibility** distinguishes these states: Active; Archived (independently); and Suppressed by an archived Song, where the Arrangement is active itself.
- **Applicability** means occasion tags (Song and Arrangement), languages and Choirs (Arrangement), and liturgical moments (Song). Empty means **Unspecified**, never universal. Arrangement filter matching belongs to search (T2.x) and is not built here.
- **Reference safety.** The domain cannot see Mass plans or snapshots. Callers report durable references as `DurableReference` values, and the domain decides the verdict. A Song can be deleted only when it is archived, has no Arrangements at all, and has no other references. An Arrangement can be deleted only when it is archived and has no references.
- **Tests.** `tests/song-library` becomes a new workspace test crate, `song-library-tests`. It has only a dev-dependency on `domain`, mirroring `tests/storage`, and adds no new external crate.

## Work packages

### WP1: Model and Interface (T2.3a). Design-sensitive: new invariants. AC1, AC2, AC3, AC4.

Files: `crates/domain/src/song_library/{mod.rs,interface.rs}` and `crates/domain/src/song_library/model/{mod.rs,song.rs,arrangement.rs,choir.rs,text.rs}`.

Types:
- `SongWork`, `Arrangement`, `Choir`, `ArchiveState`.
- `PaginationState { Draft, Approved, NeedsReview }`. A change to lyrics, labels, sections or Sequence moves `Approved` to `NeedsReview`.
- `SongLibrary` with these operations:
  - Create, edit and read Song works, Arrangements and Choirs.
  - Choir associations: set, add and remove, with shared Arrangements allowed.
  - Choir repertoire.
  - Approve pagination.
- Validation errors are stable variants.

### WP2: Retention and evidence (T2.3b). Design-sensitive: deletion safety. AC5, AC6, AC7.

- Archive and restore for Songs, Arrangements and Choirs, non-cascading.
- `visibility`, `selectable_arrangements`, and `songs(StatusFilter)`.
- `deletion_verdict` and `delete_*` from caller-reported `DurableReference`s.
- `normalize_for_match` and `duplicate_evidence`.
- Editing an archived entity is refused, because archived entities are inspect-only until restored.
- A test asserts the Interface has no merge or redirect operation.
