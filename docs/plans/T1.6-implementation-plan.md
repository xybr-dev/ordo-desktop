# T1.6 implementation plan

## Outcome

The packaged app enters and leaves Presenter Mode safely in one window, and
congregation output is real. **Enter Presenter** turns the main window into
native full-screen Live Control. Output starts disabled, with no output window.
**Enable Output** opens one passive black window on the assigned display. That
window draws the same frames as Program. **Exit Presenter** is direct while
output is disabled. While output is enabled it asks **End presentation?**, then
forces Program black, closes output, leaves full-screen and restores the
preparation workspace as it was. A display that disappears is reported at once
and never replaced by the operator display. The same display returning is
noticed with no key press, and `Space` resumes in one step (Decision 272). On
Windows, "the same display" means the same monitor (friendly name and EDID
maker/product), not only the same resolution.

## Shaping constraints (verified)

- **The Engine already has the lifecycle.** `presentation::commands::Command`
  has `EnableOutput`, `DisableOutput`, `DisplayLost` and
  `DisplayReturned { recognized }`. `LiveState` has `OutputDisabled`,
  `EnabledBlack`, `Live`, `Frozen`, `Blackout` and
  `Disconnected { display_back }`. The Dock's primary control already reads
  **Enable Output** and **Resume Output** (`presenter/dock.rs:802-809`).
  T1.6 adds no Engine command. It connects the platform to these commands.
- **The Engine accepts `EnableOutput` with no display.** The refusal belongs
  to the output controller (WP3). With no assignable display the operator
  stays in Output disabled with the status "No congregation display found —
  rehearsing on Preview" (owner decision, 2026-11-04). Output never opens on
  the operator display (Decisions 48 and 54).
- **Today `PresenterView` exists only in `live-control-lab`.** The packaged
  shell has `EnterPresenter`/`LeavePresenter` actions
  (`shell.rs:1137-1141`), but they only change the UI environment.
  `ShellView` already owns all preparation state: destination, selections,
  `list_scroll`, `viewer_scroll`, `editor_scroll`, the masses index and
  disclosure. So entry keeps the same `ShellView` entity alive. Its root renders
  the Presenter in place of the preparation chrome, and exit renders the
  chrome again from untouched state. Nothing is serialized, and nothing is
  rebuilt (Decision 203).
- **Native full-screen.** `Window::toggle_fullscreen` and
  `Window::is_fullscreen` (`gpui-pre-0.3.8/src/window.rs:2779`, `:6502`).
  Entry records `window.window_bounds()` (Windowed, Maximized or Fullscreen)
  before toggling. Exit toggles back only if it toggled in, so a window that
  was already full-screen stays full-screen.
- **Phase-0 output is a separate stack.** `crates/ordo/src/output.rs`
  (`CongregationOutput`) holds its own `PresentationEngine` and a raster
  `CongregationView` (`lib.rs:168`, ProgramFrame → RGBA → PNG). T1.6 does not
  reuse that path for the Presenter. The congregation window draws **the same
  `Arc<Frame>`** and decoded image as the Program monitor, from the
  Presenter's `PresenterFrames` store, through `live_viewport`. Decision 310
  retired raster for live output. The Phase-0 path stays for the labs and
  `NativeRuntime` until a later task retires it.
- **What T1.6 keeps from Phase 0:** `platform::display::DisplayControl`
  (assignment, `enable_output` placement, `refresh` → `DisplayEvent`,
  recognition), `congregation_window_options`, re-activating the operator
  window after a click on the passive window, and the cursor locator
  (`output.rs:109-157`).
- **Display changes are window-driven, never polled.** The vendored GPUI
  patch (Decision 308, `vendor/gpui-pre-windows/src/events.rs:952`) fires
  each window's `moved` callback on every `WM_DISPLAYCHANGE`. After a
  disconnect the output window is gone. The **operator** window's bounds
  observer is what notices the return, with no key press.
- **GPUI's display uuid is the port, not the monitor.** It is
  `Uuid::new_v5(NAMESPACE_DNS, be_bytes(szDevice))` of the GDI device name
  `\\.\DISPLAYn` (`vendor/gpui-pre-windows/src/display.rs:196`). WP7 reads
  `DISPLAYCONFIG_SOURCE_DEVICE_NAME.viewGdiDeviceName` and the target's
  friendly name and EDID IDs through `QueryDisplayConfig` and
  `DisplayConfigGetDeviceInfo`. It correlates them with GPUI's display by
  computing the same uuid from the same device name. Blank or generic names
  ("Generic PnP Monitor", "Generic Non-PnP Monitor") count as no name.
- **`unsafe` is allowed in exactly one module today** (Decision 269;
  `xtask` `UNSAFE_EXCEPTION`). WP6 records the amending decision *before*
  WP7's code. `xtask` then allows exactly the two named modules.
  `windows-sys =0.61.2` gains the `Win32_Devices_Display` feature; no new
  crate. Issue #81 carries scope, blast radius and rejected alternatives.
- **Cursor hiding is not available.** GPUI's `CursorStyle` has no hidden
  variant, and Win32 `ShowCursor` needs `unsafe`. The locator remains the
  answer (Decision 56). The physical check stays under the `[MANUAL]`
  packaged row. This plan adds no third `unsafe` module for it.
- **Out of scope:** the session journal, "mark session complete" and
  clearing interrupted recovery (T1.7). Exit leaves a `// T1.7` seam that
  calls an injected `on_session_ended` hook, which is a no-op today. Also out
  of scope: emergency editing, the Settings → Displays page (Decision 202),
  and Output Fit.

## Work packages

### WP1 — Same-window entry and exit (T1.6a) · GPUI-facing

AC1, AC2, part of AC4.

- `crates/platform/src/presenter_mode.rs` (new). This is a pure enter/exit
  state machine with no GPUI types: `PresenterMode::{Preparation, Presenter
  { restore: WindowRestore, toggled_fullscreen: bool }}`. `WindowRestore` is
  `Windowed(bounds) | Maximized(bounds) | Fullscreen(bounds)`, a platform copy
  of GPUI's `WindowBounds` so the logic is unit-testable. `exit_plan(output:
  OutputState) -> ExitPlan::{Direct, Confirm}`.
- `crates/ordo/src/shell.rs`. `ShellView` gains `presenter:
  Option<Entity<PresenterView>>`.
  - **Enter:** record the window state, build `PresenterView` from the shell's
    fixture snapshot, toggle full-screen, and focus the timeline.
  - **Render:** while `presenter` is `Some`, render only the Presenter. The
    rail, header, overlays and regions are not mounted. The preparation state
    fields are untouched.
  - **Exit:** drop the Presenter, toggle full-screen back if entry toggled it,
    restore the bounds, and return focus to the element that had it.
  - The existing `EnterPresenter`/`LeavePresenter` actions drive this. A
    visible **Present** entry in the preparation header uses them too.
- Tests:
  - Entering and leaving keeps the destination, the selected row, every
    scroll offset and the masses filters/folds identical. Assert values, not
    just that the code runs.
  - No second window exists after entry (`cx.windows().len()`).
  - Output starts `OutputDisabled`, and there is no output window.

### WP2 — Session header and guarded exit (T1.6a) · GPUI-facing

AC4.

- Move `presenter/header.rs` to `presenter/session_header/` (`mod.rs`, plus
  `exit.rs` for the confirmation). Add **Exit Presenter** to the header, with
  no key binding (Decision 179).
- The **End presentation?** confirmation is a centered `ui` dialog, used only
  while output is enabled.
  - Initial focus is on **Stay in Presenter**. `Modal` focus context, so every
    single-key command is suspended (T1.5 registry).
  - Esc means Stay.
  - Program is unchanged while the dialog is open.
  - Confirm runs: `ToggleBlackout`-to-black (or the Engine's existing black
    path) → close output (WP3, a no-op until T1.6b) → `DisableOutput` →
    `on_session_ended` (T1.7 seam) → shell exit (WP1).
- Tests:
  - Direct exit when output is disabled.
  - Confirm appears when enabled: keys are suspended and Program is unchanged.
  - Cancel keeps everything.
  - Confirm order: black is published before close (a recorded event list).

### WP3 — Output controller (T1.6b) · design-sensitive

AC3, AC4.

- `crates/platform/src/display/output_controller.rs` (new, no GPUI window
  types). It wraps `DisplayControl` and turns the operator's intent plus the
  topology into an `OutputAction`:
  - `Open(OutputPlacement)`;
  - `Close`;
  - `Refuse(OutputRefusal)` — `NoDisplay`, `NotAssigned`, `Unavailable` and,
    from WP5 on, `DifferentDisplay`, each with operator text.
- **Enable:** refresh the topology. With no candidate display → `Refuse(NoDisplay)`
  and no Engine command. If no display is assigned and exactly one candidate
  exists, assign it (Decision 50's suggestion). Otherwise refuse with **Select
  display**. On success the order is: `Open` → `EnableOutput`, so Program is
  black before `Space` can take anything live.
- **Disable/exit:** black first, then `Close`.
- Owned by `PresenterView`, behind a trait so tests inject the in-memory
  adapter (`InMemoryDisplayAdapter`, as `output.rs` already does).
- Tests (pure):
  - No display refuses with the rehearsal status, and the Engine is not
    called.
  - One candidate is auto-assigned and opens.
  - Two candidates and none assigned refuses with Select display.
  - Never `Open` on the operator display.

### WP4 — Shared-frame congregation window (T1.6b) · GPUI-facing

AC3, AC4.

- `crates/ordo/src/presenter/output_window.rs` (new). It holds a passive view
  that holds the Presenter's `Entity` and draws Program through the same
  `live_viewport` and `Arc<Frame>`. No operator-only element: no Preparing
  badge, AUTO badge, progress bar or marks. Black when the Engine's Program is
  black.
- It opens with `congregation_window_options(placement)`. After a click it
  re-activates the operator window (as `output.rs` does). Pointer enter/leave
  drives the cursor locator in the Presenter header area (Decision 56).
- Tests:
  - `Arc::ptr_eq` between the Program monitor's frame and the output window's
    frame after `Take`.
  - The output window has no operator-only selectors.
  - The output window exists only between Enable and Exit/Disable/Lost.
  - Exit: black is painted before the window closes.

### WP5 — Display loss and return (T1.6c) · design-sensitive

AC5, AC6.

- An operator-window bounds observer (`cx.observe_window_bounds`), owned by
  `PresenterView` and dropped with it, calls `OutputController::refresh`.
- `DisplayEvent::Lost` for the active display → close the window and send
  `DisplayLost`. The header health shows Disconnected, and Program shows the
  disconnected placeholder (Decision 49). Output is never moved.
- A return → `recognize(evidence, topology)`:
  - The same display → `DisplayReturned { recognized: true }`, and the primary
    control reads **Resume Output**.
  - `Space` or Resume → controller `Open` on that display → `Take`
    (Decision 272), with the ordinary 500 ms fade.
  - Any other display → `DisplayReturned { recognized: false }`. `Space` is
    refused with the reason, and recovery goes through **Select display** /
    **Enable Output**.
- Tests (in-memory adapter):
  - Loss with no key press sends `DisplayLost` and closes the window.
  - The same display returning shows Resume Output with no key press.
  - `Space` reopens and goes Live.
  - A different display with the same resolution but a different name is
    refused.
  - Output never opens on the operator display.

### WP7 — Monitor identity (T1.6d) · design-sensitive

AC7.

- `crates/platform/src/display/monitor_identity.rs`, Windows-only with `cfg`.
  Off Windows it returns an empty map.
  - `QueryDisplayConfig(QDC_ONLY_ACTIVE_PATHS)`, then for each path
    `DisplayConfigGetDeviceInfo` for the source name (`viewGdiDeviceName`) and
    the target name (`monitorFriendlyDeviceName`,
    `edidManufactureId`/`edidProductCodeId`).
  - Returns `HashMap<Uuid, MonitorIdentity>`, keyed by the GPUI-equivalent
    uuid.
  - A pure `fn normalize(raw) -> Option<MonitorIdentity>` treats blank and
    generic names as no name, unit-tested without `unsafe`.
- `gpui_adapter.rs` fills `DisplayEvidence::name` from the map. Recognition
  compares name and EDID when both sides have them, and falls back to the
  current rule when neither does.
- `windows-sys` gains the `Win32_Devices_Display` feature on the pinned
  version.
- Tests:
  - `normalize` cases.
  - Recognition with the same resolution but different names is refused; the
    same name passes; no names falls back.
  - A Windows-only smoke test reads at least the primary monitor and never
    panics.

## Risks

- **HDMI extenders and switches** may report a generic name or no EDID, which
  would cause false refusals. The fallback rule (no names → the current
  resolution rule) and the church-cabling `[MANUAL]` row cover it.
- **Full-screen toggling while a modal or the rail overlay is open.** Entry
  and exit close transient surfaces first.
- **Phase-0 `NativeRuntime` still opens `CongregationOutput`.** Make sure the
  shell's Presenter never drives both. The Phase-0 controller stays idle in
  the packaged app once the Presenter owns output.
