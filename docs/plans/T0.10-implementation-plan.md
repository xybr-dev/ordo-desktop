# T0.10 implementation plan

> Active plan. `MILESTONES.md` owns T0.10's status and acceptance gates; this
> file owns only the order in which the work lands. Freeze it at the gate close.
> Stacked on T0.9 (PR #45): branch `t0.10-qualification-gate` from
> `t0.9-powerpoint-spike`.

## Outcome

Close Phase 0 with one reproducible qualification bundle and an enforced
architecture record:

- `cargo xtask qualify` runs, from one commit, every automated Phase 0 proof
  that a Windows runner can execute and writes one indexed bundle under
  `target/qualification/milestone-0/`.
- Every report in the bundle is tied to the same provenance: `index.json`, a
  sidecar per artifact, and a header on each log.
- xtask enforces the reuse rule for spikes.
- `docs/qualification/milestone-0/` records what each proof covers, the
  exception ledger, and the manual sign-off sheet.

Constraints that shape the split:

- **Provenance block (AC1).** Every report needs a JSON object `provenance` with
  these fields:
  - `commit`: `git rev-parse HEAD`.
  - `dirty`: `git status --porcelain` is non-empty.
  - `rustc`: `rustc -vV`, both the release and host lines.
  - `cargo`: `cargo -V`.
  - `toolchain_file`: the channel from `rust-toolchain.toml`.
  - `gpui`: `[workspace.metadata.ordo.gpui-supply]`, plus the versions of
    `gpui-pre`, `gpui-pre-platform` and `gpui-base` in `Cargo.lock`.
  - `dependencies`: the SHA-256 of `Cargo.lock`.
  - `os`: on Windows, `cmd /C ver` plus `PROCESSOR_ARCHITECTURE`.
  - `gpu`: the `Win32_VideoController` Name/DriverVersion via
    `powershell -NoProfile -Command "Get-CimInstance ..."`. If that is
    unavailable, record `"unknown: <reason>"`, never an empty string.
  - `fixtures`: per-tree SHA-256, plus one aggregate SHA-256.

  The fixture hashes use the T0.8 fingerprint rule: sort relative paths
  bytewise, hash `path\0sha256\n` lines. The trees are `tests/fixtures`,
  `tests/golden-frames`, `tests/native-runtime/golden`,
  `crates/rendering/tests/fixtures` and `contracts`.

  Provenance is collected by the external tools xtask already shells out to. It
  adds no new runtime dependency, and none of it ships in the product.
- **Bundle (E2E, AC1).** `qualify [--allow-dirty]` runs these steps in order, each with its own
  captured log and status `pass | fail | missing`:
  1. `cargo xtask verify` (workspace contracts, offline, tests, deny).
  2. `cargo build -p ordo --release --locked`, the native package.
  3. `cargo test -p native-runtime-tests --locked --test canonical_invariance`.
  4. `cargo test -p display-tests --locked --test native_display`.
  5. `cargo test -p rendering --locked --test shaping_probe`.
  6. `cargo xtask measure-presenter`, whose report is copied into the bundle.
  7. Export the T0.9 fixture deck, then `inspect-pptx` it.

  The spike step runs `cargo run -p powerpoint-spike -- fixture`.

  Output:
  - `index.json` holds provenance, the steps, durations and exit codes, and
    per-artifact SHA-256.
  - `index.md` is a human-readable table of the same.
  - `logs/<step>.log` holds each step's captured output.
  - `artifacts/...` holds the copied reports.

  `qualify` exits non-zero if any step is `fail` or `missing`. A failed step
  does not stop the later ones, so every result is recorded. A rerun writes a
  new `runs/<UTC timestamp>-<short commit>/` directory and refreshes
  `latest.txt`, so failures and reruns are retained (the AC2 wording).

  The step list is data (`const STEPS`) so later phases append to it, which is
  the reuse the AC asks for. `--skip <step>=<reason>` marks a step `skipped`
  with that reason (for example, covered by another CI job). Skipped steps do
  not fail the exit code, but `index.md` lists them prominently, and only a
  bundle with zero skipped, failed or missing steps is marked `complete: true`.
- **Packaged checks (`[MANUAL]`).** There is no installer before T6. "Native
  package" here means the release `ordo` binary that the T0.3/T0.4a gates
  already qualify. The Windows 10 22H2 sign-off is a manual sheet,
  `docs/qualification/milestone-0/WINDOWS-10-SIGNOFF.md`. It references a
  bundle by commit and aggregate fixture hash and keeps failed attempts as rows.
  Linux packaged sign-off is retired to T6.2 (Decision 268).
- **Reuse rule (AC5).** xtask's dependency check gains one rule: no package
  outside `tests/*` may depend on any spike package, at any dependency kind. A
  spike is a package whose name ends in `-spike`, or whose manifest lies under
  `tools/` in a directory ending in `-spike`.
  `tools/ui-lab` and xtask are included in that.

  Test packages may reach spikes only through `[dev-dependencies]`.

  Reusable assets live outside `tools/*-spike`:
  - contracts in `contracts/`;
  - fixtures in `tests/fixtures/`;
  - the PowerPoint inspector in `xtask/src/inspect_pptx.rs`;
  - instrumentation in `xtask/src/measure_presenter.rs` and `tests/performance`.

  A test asserts the current tree passes the rule, and that a synthetic edge
  from `ordo` to a spike fails it.

  Known gap, recorded in the ledger: the `.ordo` container inspector is still
  spike code. It is promoted into the `portability` crate at its owning
  milestone, and until then only tests reach it.
- **Exceptions ledger (AC3).** `docs/qualification/milestone-0/EXCEPTIONS.md`
  lists every workaround Phase 0 adopted, taken from the qualification docs and
  plan Deviations sections (T0.3–T0.9). For each it records the owning Adapter
  or Module, the proof that requalified it, and confirmation that `domain`
  stays independent of it. That confirmation is already enforced by `xtask
  architecture`.
- **Manual review.** Run `cargo xtask qualify`, then open
  `target/qualification/milestone-0/latest.txt` → `index.md`.
  `cargo run -p ordo` still launches the walking skeleton.

## Work packages

```
WP1 (xtask qualify + provenance + CI) ─┐
WP2 (spike reuse rule in xtask lib)  ──┼─► merge ─► full `cargo xtask qualify` run
WP3 (milestone-0 docs + ledger)      ──┘
```

All three run in parallel.

| WP | Owns (exclusive) | Serves |
|----|------------------|--------|
| WP1 | `xtask/src/qualify.rs` (new), `xtask/src/main.rs`, `xtask/Cargo.toml`, `Cargo.lock`, `.github/workflows/verify.yml` | AC1, E2E |
| WP2 | `xtask/src/lib.rs` | AC5 |
| WP3 | `docs/qualification/milestone-0/**`, `MVP-PLAN.md` (Phase 0 status line only) | AC2/AC3/AC4 records, E2E index doc |

WP1 also adds a `windows-qualification` CI job. It runs `cargo xtask qualify`
with `verify` and `measure-presenter` skipped as covered by their own jobs, and
uploads `target/qualification/` as an artifact. The job fails on any failed
step or provenance problem. The `complete: true` bundle comes from a local
full run.

## Deviations

- **Evidence only inside a bundle.** A report counts as qualification evidence
  only when it sits inside a bundle, meaning `index.json` plus the per-artifact
  sidecar. CI-uploaded standalone reports, such as `presenter-performance-report`,
  are diagnostic only. The "same provenance" requirement above is met by
  `index.json`, the sidecars, and the log headers.
- **`--allow-dirty`.** A dirty working tree fails the run unless `--allow-dirty`
  is passed, which records a warning. `complete` is false either way, because
  qualification needs one clean commit.
- **`current_exe` instead of `cargo xtask`.** Steps invoke xtask subcommands
  through the running xtask executable, not a fresh `cargo xtask` resolution.
- **Step timeout.** Each step has a 120-minute timeout. A timeout is recorded as
  `fail`.
- **`unknown:` and absent fixtures are problems.** Provenance values beginning
  `unknown:` and expected fixture trees that are absent are recorded, fail the
  run, and make `complete` false.
- **Spike detection by name and path.** A spike is a package whose name ends in
  `-spike`, or whose manifest lies under `tools/` in a directory ending in
  `-spike`. The path clause stops a renamed spike from escaping the reuse rule.
