# T2.5 implementation plan

## Outcome

The operator can create a Song work on its own, before any Arrangement exists:

- **New song** (list header) and **Create song** (empty Library) open a New song panel over the Songs workspace.
- **Primary title** is the only required field. Composer or original author, aliases and usual moments are optional. The panel asks for no lyrics, language, Choir, section, Sequence or slide-boundary data.
- While the operator types, Ordo ranks **possible existing Songs** from normalized identity evidence and shows them as a collapsed count ("2 possible existing Songs"). Nothing is ever selected automatically.
- Expanding the count lists the candidates. Choosing one opens a nested, identity-only preview. **Back** returns to the form exactly as entered. **Use this existing Song** abandons creation and selects that Song in the Library.
- **Create song** commits once and selects the new Song, whose detail shows **No Arrangements yet** with **Add first Arrangement**.

- `MVP-PLAN.md` 6.15.

## Shaping constraints (verified)

- **The domain already has exact-key evidence.** `SongLibrary::duplicate_evidence` (`crates/domain/src/song_library/interface.rs`) pairs title and alias `match_key`s and orders by Song creation time. T2.5 needs ranking, one entry per Song, and near matches ("Enter a near-duplicate title" in the E2E). `match_key` folds only case and spacing (T2.3 AC5) and must stay that way: it guards exact duplicates.
- **Near matches need a second, looser key, for evidence only.** T2.4's search already folds diacritics (`search.rs`). The identity key reuses that fold and also drops punctuation. It is never stored, never rewrites authored text and never blocks creation.
- **Numbered settings stay separate (Decision 39).** "Kyrie I" and "Kyrie II" differ after folding, so they are not near matches of each other. The identity key must keep digits and roman numerals as written.
- **Storage is ready.** `Storage::create_song(NewSong)` generates the id and stores a Song with no Arrangement. `SongLibrary::create_song(id, created_at, draft)` takes the caller's id, so the store applies the returned record as `create_choir` does.
- **One write queue.** `LibraryStore` serializes writes through `submit` / `pump` with a `ChoirWrite` enum. Song creation joins the same queue, so the order of a Choir write and a Song write is the order they were submitted.
- **The form's fields are the mockup's four.** Occasion tags, provenance and rights notes are optional identity metadata in `SongDraft`, but the approved form does not show them. They stay editable later through Song details (T2.6 / T2.9 surfaces). "Optional identity metadata matches the adopted Song-work ownership" (AC2) is met by the four fields all being Song-work fields (Decisions 88, 117) and by the absence of every Arrangement-owned field.
- **Add first Arrangement has no target yet.** T2.6 builds Arrangement creation. Following the owner's T2.4 decision for actions whose target is not built, the button is shown and disabled with a reason until T2.6.
- **E2E location.** `tests/e2e/` does not exist. As with T1.4, T1.6, T1.7 and T2.4, the E2E lives in the crate: `crates/ordo/src/songs/e2e.rs`. WP4 amends the task's Changes line.
- **Panel hosting.** The shell hosts focused views through `ShellView.editing`. The New song panel is not a focused editor: it is an overlay owned by `SongsWorkspace`, so the workspace state (query, filters, selection, scroll) is untouched underneath it.

## Work packages

### WP1: Ranked possible existing Songs (T2.5a). Design-sensitive: matching semantics. AC3.

New `crates/domain/src/song_library/duplicate_evidence.rs`. The existing `MatchedOn`, `DuplicateEvidence` and `duplicate_evidence` move here unchanged (re-exported as before), and the module adds:

- `identity_key(text) -> String`: `match_key`, then the search diacritic fold, then punctuation and spaces dropped, keeping letters and digits as written. A dropped run between two digits leaves one space, so neighbouring numbers never join ("Psalm 1-2" and "Psalm 1 2" match, "Psalm 12" does not).
- `SongLibrary::possible_existing_songs(&self, candidate: &SongDraft) -> Vec<PossibleSong>`.
- `PossibleSong { song: SongId, strength: MatchStrength, evidence: Vec<IdentityEvidence> }`, one per Song, archived Songs included.
- `IdentityEvidence`, an enum: `Name { candidate_on: MatchedOn, existing_on: MatchedOn, exact: bool }` for each title or alias pair that matches, and `SameAttribution` when both sides have a composer and their identity keys are equal.
- `MatchStrength`, strongest first: `ExactTitle` (title to title, `match_key` equal), `ExactAlias` (any exact pair involving an alias), `NearTitle` (title to title by identity key only), `NearAlias`.
- Order: strength, then Songs with `SameAttribution` first, then title `match_key`, then id. A composer match alone never makes a candidate.
- A blank candidate title with no aliases returns nothing. A name with no letters or digits ("♫", "?!") has an empty identity key; it matches only an equal `match_key`, as an exact pair.

Tests in `tests/song-library/tests/duplicates.rs`, through the public Interface.

### WP2: `LibraryStore::create_song` (T2.5a). Design-sensitive: write ordering. AC6 (store half).

- `ChoirWrite` becomes `LibraryWrite` with a `CreateSong(SongDraft)` variant.
- `create_song(draft, cx) -> Task<Result<SongId, SharedString>>`: domain validation first (blank title, duplicate or blank alias refuse without I/O), the storage write off-thread through the queue, then the returned record applied to the in-memory library, then `LibraryEvent::Changed`.
- An exact duplicate title is **allowed**: Decision 38 leaves the choice to the operator, and the panel shows the evidence.
- Tests: storage-backed create then reopen shows the Song with no Arrangement; a failed write leaves memory unchanged; a Choir write and a Song write keep submission order.

### WP3: New song panel (T2.5b). GPUI-facing. AC1, AC2, AC4, AC5, AC6.

`crates/ordo/src/songs/new_song/{mod.rs, form.rs, preview.rs, tests.rs}`:

- `NewSongPanel` entity owned by `SongsWorkspace`. Fields: Primary title (required), Composer or original author, Aliases (comma separated), Usual moment (comma separated). Copy from the mockup.
- **Create song** is disabled while the title is blank and while a create is in flight, so it commits once. Enter in the title field does the same. Cancel and Escape close the panel and discard the form.
- The possible-existing count is a collapsed disclosure under the title. Expanding lists candidates in WP1 order (title, composer, Arrangement count, Archived badge).
- Choosing a candidate opens the nested preview ("Existing Song · preview only"): title, aliases, composer, usual moments and a compact Arrangement summary (label, languages, Choirs). No lyrics, no editing. **Back** and Escape return to the form with every field, the disclosure state and focus as they were. **Use this existing Song** closes the panel, turns Include archived on when the Song is archived, and selects it.
- After a successful create the panel closes and the workspace selects the new Song. A failed create keeps the panel open with **Couldn't create song** and the form intact.
- `list.rs`: New song and Create song are enabled when the store is ready. Import `.ordo` stays disabled.
- `detail.rs`: a Song with no Arrangements shows **No Arrangements yet**, the mockup's sentence, and **Add first Arrangement** (disabled with a reason until T2.6).
