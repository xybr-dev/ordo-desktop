# T2.6 implementation plan

## Outcome

The operator can create an Arrangement for a Song, revise its metadata, and branch it:

- **Add first Arrangement** / **Add Arrangement** (Song detail) opens **New Arrangement**; **Arrangement details** (focused Arrangement header) opens the same surface for an existing Arrangement.
- At least one language is required, chosen from Ordo's built-in list. Display title, Choirs, translator or adapter, occasions and notes are optional. A blank display title shows a label derived from languages and Choirs.
- Nothing is stored until **Create Arrangement** or **Save details**. Cancel and Escape discard the staged metadata and leave the page underneath as it was.
- Editing an Arrangement shared by several Choirs states that scope before Save. **Duplicate Arrangement** branches it into an independent Arrangement with its own revision history.
- Save details writes one Edit revision. Snapshots and Mass references are not touched.

## Shaping constraints (verified)

- **Paths in the task's Changes line do not exist.** The domain keeps Arrangements in `crates/domain/src/song_library/model/arrangement.rs` and `interface.rs`; the UI goes in `crates/ordo/src/songs/arrangement_details/`; the E2E joins `crates/ordo/src/songs/e2e.rs`. WP5 amends the Changes line.
- **Title is required today in four layers.** `ArrangementDraft.title: String`; `arrangement.title TEXT NOT NULL CHECK (length(trim(title)) > 0)` (migration 0003); `validate_arrangement_fields` in `crates/storage/src/parish_store/write.rs` (shared by create and revision commit); `ArrangementContent`/`ArrangementDoc` in `crates/storage/src/revisions/content.rs` (`deny_unknown_fields`, `format = 1`).
- **SQLite cannot relax NOT NULL in place.** Migration 6 rebuilds `arrangement`. Migration SQL runs inside the runner's transaction (no BEGIN/COMMIT; `PRAGMA foreign_keys` is a no-op there). Six tables reference `arrangement` (`arrangement_language`, `arrangement_choir`, `arrangement_occasion`, `arrangement_section`, `section_occurrence`, `edit_revision`). The rebuild uses `PRAGMA defer_foreign_keys = ON`, copies rows aside, drops and recreates `arrangement` under the same name (with `pagination_state`, its CHECK and `arrangement_by_song`), and copies back, so the deferred violation count returns to zero before commit. A test migrates a populated version-5 parish and runs `PRAGMA foreign_key_check`.
- **Existing revisions must still read and verify.** Stored revision payloads are content-hashed. Format-1 payloads (title always present, no notes) must load unchanged; they are never re-serialized. New payloads may use a new format number.
- **No built-in language list exists.** Choir preferred languages and Library filters use free text. T2.6 adds the list to the domain and uses it for Arrangement languages only; Choir languages and filters keep working on whatever strings are stored.
- **Storage already writes creation revisions** (`append_creation` inside `insert_arrangement`). The only update path is `Storage::commit_arrangement_edit(arrangement, content, pagination, kind, session, expected_parent)`; `Edit` requires a History session. `LibraryStore` has no Arrangement write and never commits a revision today.
- **Snapshots and Mass-local overrides have no writers yet.** `presentation_snapshot` and friends are placeholder tables. AC6 is evidenced by a storage test that a metadata commit adds exactly one revision row and leaves every other table's rows unchanged, and by sections, Sequence and pagination state being byte-identical after it.
- **The surface is the existing slideover.** `ui::Overlay::slideover` with `primary_gated` is the viewport-bounded floating surface T2.5 used; `SongsWorkspace.overlays` / `OverlayHost` host it. The `ui` crate has no multi-select; the panel composes chips plus a search popover.
- **There is no Lyrics task yet (T2.7).** The focused Arrangement view is the read-only `ArrangementOverview` (`crates/ordo/src/songs/library/arrangement.rs`) opened by `ShellView::open_arrangement`.
- **Choir quick-create exists inline** (`crates/ordo/src/songs/choirs/quick_create.rs`, `offer`). It offers archived Choirs; the Arrangement picker must not (Decision 221, mockup F).

## Decisions made while planning (owner to confirm)

1. **One notes field.** The AC lists "source, rendition, and rights notes"; the approved mockup shows one box, **Source and rights notes**. The plan follows the mockup: one optional `notes` text on the Arrangement. Splitting later is an additive migration.
2. **Creation lands in the focused Arrangement view.** Until T2.7 builds Lyrics, **Create Arrangement** opens the focused view, which shows **No sections yet** and a disabled **Add first section** with a reason. T2.7 replaces the body.
3. **The shared-scope warning is the mockup's notice,** shown above the fields before Save, not a second confirmation dialog.
4. **Duplicate copies the stored Arrangement,** not the staged edits: title, languages, Choirs, attribution, occasions, notes, sections and Sequence, with new section and occurrence identities, Draft pagination and a fresh Creation revision. The panel closes and the duplicate opens in the focused view.
5. **Each Save details is its own History session.** It is an explicit commit, not coalesced typing.
6. **Derived label Choir order is by Choir name** (match key, then id), so the label is stable.
7. **Held languages may be kept.** A details or lyrics edit may keep any language the Arrangement already holds, even one outside the built-in list (a parish stored before this task); only languages being added must be built in. A copy is a creation, so an Arrangement with no language cannot be duplicated. The fallback label when there is no title, language or Choir is `Untitled`.

## Work packages

### WP1: Domain metadata, derived label, languages, duplicate (T2.6a). Design-sensitive: new invariants. AC2, AC6 (domain half).

- `ArrangementDraft.title` becomes `Option<String>` (present means not blank); new `notes: Option<String>` (same rule). `ArrangementDraft::titled` stays; add `ArrangementDraft::in_language(language)`.
- **At least one language** is required on create and on a details edit (`BlankField(Field::Language)`). Hydration stays lenient so existing parishes load.
- New `crates/domain/src/song_library/languages.rs`: the fixed list from the mockup's `LANG_CATALOG` (display name, other names), `languages()`, `find_language(query)` returning matches with the alias that matched, `is_listed(name)`. Lookup folds case and diacritics like `search.rs`.
- `ArrangementDetails { title, languages, choirs, rendition_attribution, occasions, notes }` and `SongLibrary::edit_arrangement_details(id, details)`: one atomic replacement of metadata and Choir associations that keeps sections, Sequence and pagination state; refused wholesale on any invalid part. `Arrangement::details()` returns the current value.
- `SongLibrary::arrangement_label(id) -> String`: the title when present, else languages joined with " + ", then " · {first Choir}" and " +{n}" for the rest (`arrLabel`).
- `SongLibrary::duplicate_arrangement(source, new_id, created_at, section_ids, occurrence_ids)`: an independent copy under the same Song with the caller's new identities, Draft pagination, active state. Refused for an archived Song; an archived source may be duplicated; archived Choirs are dropped from the copy.
- Ripple: update `hydrate.rs`, `search.rs`, `duplicate_evidence.rs` and every caller in `storage` and `ordo` so the workspace compiles and behaves as before (a stored title maps to `Some`). No schema change in this package.
- Tests through the public Interface in `tests/song-library/tests/arrangements.rs`, named `ac2_*` and `ac6_*`.

### WP2: Migration 6 and storage (T2.6a). Design-sensitive: schema, revision format. Read fully. AC2, AC6.

- `migrations/0006_arrangement_details.sql`: rebuild `arrangement` with `title TEXT CHECK (title IS NULL OR length(trim(title)) > 0)` and `notes TEXT` under the same rule. Register in `bundled()`, update the version assertions the 0005 change touched, the ERD notes, and re-bless `ERD.md`.
- `NewArrangement`, `ArrangementRecord`, `ArrangementContent`, `HydrateArrangement` mapping, `insert_arrangement`, `read_arrangement`, `commit_arrangement_in`, `validate_arrangement_fields`: optional title, notes, at least one language.
- Revision payload: new format carrying optional title and notes; format 1 still reads and verifies (fixture test).
- Tests in `tests/storage/tests/`: populated 5 → 6 migration with `foreign_key_check` and identical rows; create with no title; metadata commit adds one revision and leaves sections, Sequence, pagination and all other tables unchanged; restoring an older revision still works.

### WP3: `LibraryStore` Arrangement writes (T2.6a). Design-sensitive: write ordering. AC6 (store half).

- `LibraryWrite::{CreateArrangement(SongId, ArrangementDetails), SaveArrangementDetails(ArrangementId, ArrangementDetails), DuplicateArrangement(ArrangementId)}` through the same queue.
- `create_arrangement`, `save_arrangement_details`, `duplicate_arrangement` return `Task<Result<ArrangementId, SharedString>>`. Each validates in the domain first (no I/O on refusal), writes off-thread, applies the returned record, emits `LibraryEvent::Changed`.
- Save details is one atomic metadata-only commit: storage reads the head revision, sections, Sequence and pagination state in the same transaction, replaces only the metadata, appends one `RevisionKind::Edit` with a fresh session and returns the whole stored Arrangement, which memory then takes. Sections and Sequence are read in the same transaction, so a Save never overwrites newer sections. Details equal to the stored ones write nothing, add no revision and emit no event. A storage error leaves memory unchanged.
- Tests in `crates/ordo/src/songs/store/tests.rs`: create then reopen; save writes one revision; duplicate has its own identity, section identities and a one-entry history while the source history is unchanged; failed write leaves memory unchanged; submission order holds across kinds.

### WP4: Arrangement details panel and entry points (T2.6b). GPUI-facing. AC1, AC3, AC4, AC5.

`crates/ordo/src/songs/arrangement_details/{mod.rs, form.rs, pickers.rs, tests.rs}`:

- Note for this package: a stored Arrangement may hold a language that is not in the built-in list, or none at all. The panel must show held languages as chips that can stay, offer only built-in languages to add, and map the empty-language refusal (`language is blank`) to the panel's own wording.
- `ArrangementDetailsPanel::open_new(song, ..)` and `open_edit(arrangement, ..)`, one slideover. Titles, field order, hints, placeholders, errors and toasts from the mockup. No composer or original-author field.
- Languages: chips of the languages already used in the Library plus **+ Language** search over the built-in list ("also called …", no create row, the no-match sentence). Choirs: chips plus **+ Choir** search with `Create “…”` as the first row when nothing matches; archived Choirs are not suggested; a created Choir is saved at once and selected while the Arrangement stays staged.
- Create with no language shows the error beside the field and stores nothing. The primary action is gated while a write is in flight.
- Edit mode: the shared notice when the stored Arrangement has more than one Choir; **Duplicate Arrangement** in the footer.
- Cancel and Escape discard. The workspace query, filters, selection and scroll are unchanged underneath.
- Entry points: `detail.rs` enables **Add first Arrangement** and adds **Add Arrangement** for a Song that has some; the focused view header gains **Arrangement details**; rows, the focused view and the shell title use `arrangement_label`. The focused view shows **No sections yet** with a disabled **Add first section**.
- After Create or Duplicate the shell opens the new Arrangement's focused view.
