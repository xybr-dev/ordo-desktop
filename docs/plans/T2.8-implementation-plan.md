## Outcome

The operator builds the sung order of an Arrangement out of the sections written once in Lyrics:

- The **Sequence** tab of the Arrangement editor becomes editable. It keeps the three panes: **Available sections** on the left (each with an explicit **Add**), the ordered **Sequence** of occurrences in the centre, and the same canonical **Inspector** on the right.
- **Add** inserts an occurrence right after the selected occurrence, or at the end when none is selected, and selects it. **Repeat** inserts another occurrence of the selected occurrence's section right after it. Neither copies lyrics or slides. Adding a section in Lyrics never places it; the quiet **Add to Sequence** in Lyrics follows the same insertion rule.
- Occurrences read as **01 Verse 1**, **02 Chorus**, **03 Verse 2**, **04 Chorus**: position plus the unchanged section name, never "Chorus 2". A repeated section carries a **Same section** chip. Collapsed rows show the slide count; expanding one shows its generated slides in order. **Expand all** / **Collapse all** changes disclosure only.
- `Alt+Up` / `Alt+Down` or dragging the grip moves a whole occurrence with all of its slides. `Delete` on a focused occurrence row removes the occurrence (never the section) without confirmation, selects the next occurrence, otherwise the previous one, and **Undo** puts it back at its old position.
- An empty Sequence is saved as it is and shows **No performance sequence yet** with a focused **Add first occurrence**. The header shows the Arrangement's readiness: **No sections yet**, **Incomplete**, **Needs review** or **Ready**. Readiness looks only at sections the Sequence uses, reports a repeated section once with its occurrence count, and ignores unused sections.
- Pagination approval becomes per section (T2.7 Decision 3 deferred it here). Lyrics shows each section's review state and offers **Approve pagination** on a section that needs it.
- Every edit autosaves through the same `EditSession` and History session as Lyrics, and `Ctrl+Z` / `Ctrl+Y` undo Sequence and Lyrics steps in one stack.

## Shaping constraints

- **One content type, one port, one session.** Every Sequence action is a `structural` edit of the shared `ArrangementLyrics`, committed by `LyricsPort` through `save_arrangement_lyrics`. No new store write, no new port, no second `EditSession` (MVP-PLAN 6.18: "Keep Lyrics/Sequence work together for one Arrangement").
- **Domain owns the rules, the view owns selection.** Insertion position, repeat, move, removal's next/previous choice, flattening, position labels and readiness are pure domain functions in `crates/domain/src/song_library/sequence.rs` (the Changes path). The view keeps only the selected occurrence id, slide index and disclosure set.
- **Identity, not position.** Selection, disclosure and drag targets are keyed by `OccurrenceId`; positions are display labels recomputed on every render (Decision 130).
- **Readiness needs per-section approval.** AC7 ("considers only referenced sections, deduplicates repeated section findings") and Decision 129 cannot be met with one Arrangement-wide state, because an edit to an unused section would still raise the warning and the warning cannot name a section. So T2.8 moves the state onto sections (Decision 1), which T2.7 Decision 3 anticipated.
- **Approval must survive Undo and be a revision.** MVP-PLAN 6.18 makes every committed Undo point a durable Edit revision. If approval stayed outside the payload, approving would write a revision identical to its parent. So the payload carries per-section state (Decision 3).
- **Readiness cannot render.** `domain` has no rendering. "Unrenderable" (Decision 129) arrives as an input set of section ids that the editor fills from `LyricsFrames` compose failures; fit checks wait for T3.1.
- **`Delete` must never reach text.** The binding sits in context `SequenceOccurrences` under the text-entry and modal guard, and the view checks again before acting (Decision 127).
- **No compose on the GPUI thread.** Expanded children and the Inspector reuse `LyricsFrames`; repeated occurrences share one `Arc<Frame>`.
- **Changes paths.** `crates/ordo/src/songs/sequence/` and `crates/domain/src/song_library/sequence.rs` are new as written. `tests/song-library/sequence.*` becomes `tests/song-library/tests/sequence.rs` (the crate's layout). `tests/e2e/songs/sequence.*` does not exist: as for T2.4-T2.7 the E2E lives in `crates/ordo/src/songs/e2e.rs`. Migration 0007, `crates/storage/src/revisions/content.rs` and the Lyrics files are outside the Changes line; WP8 amends it.

## Decisions made while planning (owner to confirm)

1. **Per-section pagination approval lands in T2.8.** `SectionDraft` gains `pagination: PaginationState` (constructors default to Draft); `ArrangementLyrics.pagination`, `Arrangement::pagination_state()` and `SongLibrary::approve_pagination` go. *Reason:* AC7 and Decision 129 need section-level findings, and mockup B already shows "Needs review" per section. *Alternative:* keep one state and limit the review rule to referenced sections; cheaper (no migration) but the warning cannot name a section or be deduplicated.
2. **Migration 0007 shape.** `ALTER TABLE arrangement_section ADD COLUMN pagination_state TEXT NOT NULL DEFAULT 'draft' CHECK (pagination_state IN ('draft','approved','needs_review'))`; backfill `UPDATE arrangement_section SET pagination_state = (SELECT a.pagination_state FROM arrangement a WHERE a.id = arrangement_section.arrangement_id)`; then `ALTER TABLE arrangement DROP COLUMN pagination_state`. Every section inherits its Arrangement's state (an Approved Arrangement keeps all its sections approved; a NeedsReview one marks all of them for review). *Reason:* conservative, lossless, no dead column. *Fallback:* if `DROP COLUMN` is refused, rebuild `arrangement` exactly as 0006 did.
3. **Revision payload format 3 carries each section's state** (`"pagination": "draft" | "approved" | "needs_review"` in every section object). Formats 1 and 2 still decode, with every section Draft, and stay verified against their stored bytes (add a format-2 canonical-text check beside `legacy_arrangement_text`). `restore_revision` drops its `pagination` parameter: states come from the payload. *Reason:* Approve and its Undo become real revisions, and T2.9 can restore whole revisions faithfully.
4. **The review rule is per section and the Sequence never changes approval.** An Approved section whose lyrics change (Split and Join included, T2.7 Decision 4) becomes NeedsReview; a new section is Draft; rename, Lyrics reorder and every Sequence edit (add, repeat, move, remove) leave approvals as they are. `edit_arrangement` (whole content) applies the same rule using stored states by id. *Reason:* a section's slides do not depend on where it is sung (Decision 126: slides move unchanged), and placing a never-approved section surfaces its warning through readiness anyway. *Needs reconciling:* Decision 18 lists "arrangement order" among review triggers; record an amendment if the owner agrees.
5. **Approve pagination ships in T2.8, in Lyrics only.** The mockup B notice above the lyric editor, with **Approve pagination**, shows for a non-empty section that is not Approved: NeedsReview uses the mockup copy ("**Pagination needs review.** The lyrics changed since the slides were approved. Check each slide in the Inspector."); Draft uses new copy "**Pagination not approved yet.** Check each slide in the Inspector, then approve." Approve is a `structural` edit (undoable, one revision) with toast "Approved {name} pagination." A section with no slides cannot be approved. *Reason:* without it every new section stays Draft and readiness can never reach Ready; T2.7 Decision 3 deferred it here; Decision 168 keeps corrections in Lyrics. The Draft copy is new and needs approval.
6. **Readiness lives in `domain::song_library::sequence`.** `readiness(&ArrangementLyrics, unrenderable: &BTreeSet<SectionId>) -> ArrangementReadiness` with state `NoSections` ("No sections yet") → `Incomplete` (empty Sequence, or a referenced section with no slides or in `unrenderable`) → `NeedsReview` (a referenced section not Approved) → `Ready`, plus one finding per referenced section with its occurrence count. Unused sections are never examined. *Reason:* Decisions 128-129 and the mockup's `readiness` (ordo-songs.js:115); T3.13 reuses it for Mass readiness.
7. **Selection model.** The editor holds `Option<SequenceSelection { occurrence: OccurrenceId, slide: usize }>`, shared by both tabs for the visit. Opening Sequence the first time in a visit selects nothing (so **Add** appends); Add and Repeat select the new occurrence at slide 0; clicking an occurrence selects slide 0 (Decision 131); clicking a child selects that slide; within the occurrence list selection follows focus. Selection survives reorder, expand/collapse and tab switches. *Reason:* AC2 needs a reachable "none selected" state, and building the order from the start then simply appends. The Inspector's empty text when nothing is selected is new: "Select an occurrence to inspect its slides."
8. **Lyrics-side Add to Sequence.** The quiet **Add to Sequence** in the section header shows for a section not in the Sequence (mockup E, `ordo-songs.js:458`), inserts with the shared selection rule, switches to the Sequence tab and selects the new occurrence; toast as in Sequence. *Reason:* Decision 123 ("same rule from both"); the mockup handler forces an append, which Decision 123's text overrides.
9. **Drag ships in T2.8.** A grip on each occurrence row starts a GPUI drag (`on_drag`) carrying the `OccurrenceId`; dropping on a row's upper or lower half places it before or after that row (`on_drop` + `drag_over` highlight); one drop is one `structural` move. Keyboard moves stay the primary, tested path. *Reason:* AC4 says "Drag or Alt+Up/Down"; GPUI has the API. *Fallback:* if drag costs more than half a package, ship the keys and buttons and ask the owner to move drag to T3.8.
10. **Keys share registry rows.** T2.7's `Alt+Up` / `Alt+Down` rows become one pair of editing actions, **Move up** / **Move down** ("Move the focused section or occurrence"), bound under `(LyricsSections || SequenceOccurrences)` with the text-entry and modal guard; a new row `Delete` "Remove the focused occurrence from the Sequence" is bound only in `SequenceOccurrences`. All three are in `Group::Editing`. Up/Down (via `ui::list::arrows`) and Right/Left (expand/collapse) stay component-level keys, as for every list. *Reason:* `no_keystroke_is_registered_twice` and T1.5's one registry; the reference stays complete.
11. **Disclosure.** Expanded occurrences are a set of `OccurrenceId` per editor visit, not saved. New occurrences start collapsed. **Expand all** shows unless all are open, then **Collapse all**. Collapsing never changes selection or the Inspector, even when the selected child is hidden. *Reason:* Decision 108 ("changes only editor disclosure state"), AC8.
12. **Selection after Undo / Redo** is a pure function `selection_after_replace(before, after, selected)`: an occurrence that reappears is selected (Undo of a removal), otherwise the current one is kept if it still exists, otherwise the occurrence now at its old position, then the previous one, then none. *Reason:* `EditSession` carries no view metadata; AC5's "Undo restores it" should also show it.
13. **No Inspector Previous / Next in T2.8.** "Inspector follows flattened occurrence/slide position" is met by the Inspector showing the selected flattened slide with "{pos} {name} · slide {k} of {n}" (mockup), and by arrow keys moving through visible rows in flattened order. *Reason:* the approved mockup has no such controls; Decision 108 places them in the Mass editor (T3.12). *Alternative:* add them now if the owner reads AC8 as requiring them.
14. **Readiness display.** The header shows the readiness label before the save state (mockup `edHead`): plain meta for **No sections yet**, warning diamond for **Incomplete**, info for **Needs review**, live for **Ready**; its tooltip and accessible description give the reason. The Sequence tab carries the warning marker while sections exist and the Sequence is empty. Reason text with counts is new copy: "No performance sequence yet", "{name} has no lyrics and is sung {n} times", "{names} need pagination review". No click routing (T3.12/T3.13). *Reason:* AC6, AC7 and the mockup.
15. **Empty Sequence.** "Add first occurrence · {first section name}" adds the first section in Lyrics order and receives focus on arrival; with no sections, the left pane says "Write sections in Lyrics first." and the centre shows no button. Removing the last occurrence focuses that button. *Reason:* mockup D and Decision 127.
16. **Thumbnails.** Expanded children use the T2.7 fixed-size tile and `LyricsFrames`; composition on the Sequence tab covers referenced sections only, keyed by (header, body), so repeated occurrences share frames. *Reason:* AGENTS.md (no compose on the GPUI thread) and Decision 108 (same frame as the Inspector).

## Risks / unknowns

- **Migration on real parishes.** 0007 changes a column every Arrangement has. `DROP COLUMN` behaviour with the column's own `CHECK` must be proven in the migration test on a 0006 fixture; keep the 0006-style rebuild ready.
- **Format 3 and legacy verification.** Format-2 revisions become legacy and must still verify byte-for-byte; a mistake makes every existing History unreadable (`RevisionIntegrity`). Test against stored v1 and v2 fixtures before changing the writer.
- **Wide signature churn.** Removing the Arrangement-wide state touches about 80 call sites across domain, storage, store and tests. Keep WP2 and WP3 mechanical and land them together in T2.8a so `cargo xtask verify` stays green per commit.
- **T2.7b drift.** Everything marked **[T2.7b]** is planned, not built. If T2.7b names the editor, regions or registry scope differently, WP5-WP7 follow the built names; if `Alt+Up` is bound per context instead of in the registry, Decision 10 changes shape.
- **Shared Alt+Up action.** One action must dispatch to whichever pane holds focus; a handler on the editor root that reads the wrong selection would move a section while the Sequence has focus. Test both tabs.
- **`Delete` leakage.** GPUI's `Input` may not consume `delete` in every state (empty field, read-only). The view's own `allows` check must refuse when focus is not on an occurrence row.
- **Drag in tests.** GPUI's `TestAppContext` drag simulation is unproven in this repo. Test the drop handler directly; one simulated drag is a bonus.
- **Selection after Undo.** `selection_after_replace` guesses from content; Redo of an insertion selects the reinserted occurrence, which is fine, but a Lyrics Undo during Sequence work can move the selection. Acceptable, and tested.
- **Compose volume.** Expand all on a long Sequence asks for every referenced section's frames at once. Keyed caching makes repeats free; first expansion of many sections must stay off-thread and show placeholders.
- **Readiness without fit.** Until T3.1, a five-line slide renders as whatever the renderer returns and counts as renderable. The E2E keeps groups at four lines or fewer.
- **Backfilled NeedsReview.** Arrangements marked NeedsReview before 0007 put every section into review, including unused ones; harmless because readiness ignores unused sections.
