## 2. Manual scripts

### A. Operating-system theme follow — recorded complete

- Setup: launch `ordo` and `ui-lab` with System appearance.
- Steps: change the OS theme light to dark and back while both run.
- Expected: System appearance (lab status line, shell surfaces) follows live
  with no restart; explicit Light/Dark choices are unaffected
  (`docs/qualification/GPUI-BASE-T0.3.md` bounds what automation covers).
- Result: tested commit `9dbea6c`; Windows 10 22H2 (build 19045.6693,
  tester-confirmed; VirtualBox "Windows 10" VM, 8 CPU / 4 GB RAM, Guest
  Additions 7.2.8); 2026-09-06; tester @xybr-dev.
  Observed: app theme followed the system theme changes live.

### B. Keyboard-only visual pass — recorded complete

- Setup: `ui-lab` at 1920x1080/100%, then `ordo` on expanded Masses. No
  pointer after launch.
- Steps: F2 through Field, Select, Combobox, Dialog, nested Slideover;
  operate each by keyboard; switch to 1366x768/200%; repeat. In `ordo`, F6
  through every region, arrows through a list, Enter into and Back out of an
  editor.
- Expected: the two-layer focus treatment (`DESIGN.md`: 2px separation plus
  2px `focus-preparation` outer) is visible on every stop including inside
  menus, dialogs, and nested slideovers; focus (blue outline) and selection
  (green fill) stay distinguishable and coexist on one row.
- Result: tested commit `9dbea6c`; same platform/date/tester as script A.
  Observed: feature parity with the Linux build, no divergences noted. Note:
  the tested commit predates the lab-root Tab handling added later on this
  branch (review round 1, P1); re-cover the F2-to-Tab leg at HEAD on rerun.

### C. Windows High Contrast — recorded complete (requires Windows for reruns)

- Setup: Windows High Contrast theme on; launch `ordo`.
- Steps: repeat script B abbreviated (rail, tabs, list, dialog, slideover).
- Expected: Ordo's own two-layer focus treatment stays fully visible in
  every surface, and selection fill, active markers, and badges keep their
  shape cues, so nothing depends on color alone. There is deliberately no
  OS-highlight deference to check: the pinned revision exposes no High
  Contrast signal and a GPU-composited GPUI window gets no system repaint,
  so Ordo paints its focus treatment in every mode (see
  `docs/qualification/GPUI-BASE-T0.3.md`, Pinned platform limitations).
  `DESIGN.md`'s allow-the-OS-highlight precedence remains the aspiration
  for a revision that reports the mode, which reruns that qualification.
- Result: tested commit `9dbea6c`; same platform/date/tester as script A.
  Observed: WHC retained Ordo's palette and focus rings as if non-WHC, as
  the expected result above requires (Ordo paints its own treatment; no OS
  deference at this pin).
